# Oathra 企業向け readiness（L1 / L2 / L3）

作成 2026-09-13。基準は「L1 企業紹介可能 → L2 有償 PoC 可能 → L3 本番導入可能」。各項目に根拠を書き、根拠が無いものは「未」とする。数字はすべて自分で計測したもの。

## 現状の判定

| 段階 | 判定 | 一言 |
|--|--|--|
| L1 企業紹介可能 | **到達（条件つき）** | デモ・再現手順・制約・コスト・失敗時挙動・ログ・ライセンスは揃っている。実電話の件数が 3 件で、L1 の「同じデモを 10 回やって崩れない」を実電話では未確認 |
| L2 有償 PoC 可能 | 未 | 録音同意・保持期間・発信制御・テナント分離・人間へのエスカレーションが未実装 |
| L3 本番導入可能 | 未 | 監視・SLO・冗長化・法令対応が未着手 |

## 最優先: 実電話 100 件の計画

目的: 「実電話 100 件、誤完了 0、成功率 XX%、p95 応答 X.X 秒、¥XX/通話」を言えるようにする。

### 前提と費用

- 相手は実在の店舗にはかけない（迷惑電話になる）。**店員役は人間（依頼者本人または協力者）が自分の番号で受ける**。100 件すべてに人が出る必要があるので、1 件 2〜3 分として 4〜5 時間の人手が要る
- 費用: 1 件 3 分 ≈ ¥110（Twilio ¥86 + GPT-Live $0.15）。100 件で **約 ¥11,000 + 米ドル $15**。着手には依頼者の明示的な go が要る（コスト方針）
- 録音には本人の声が入るため公開しない。公開するのは集計表と、本人が許可した書き起こしのみ

### 100 件の内訳（店員役の台本）

| 区分 | 件数 | 店員役がやること |
|--|--|--|
| 成功 | 30 | 希望どおりに受ける（うち 10 件は代案を出してから受ける） |
| 部分成功 | 10 | 日付か人数だけ受け、他は保留にする |
| 失敗（満席） | 10 | 全時間帯を断る |
| 留守電 | 5 | 留守番電話の応答文を読む（切らない） |
| 拒否 | 5 | 「予約は受けていません」で切る |
| 聞き返し | 10 | 「もう一度お願いします」「何名様でしたか」を 2 回以上 |
| 転送 | 5 | 「担当に代わります」→ 別の声で続ける |
| 保留 | 5 | 「少々お待ちください」で 20〜40 秒無音 |
| 騒音 | 5 | テレビや水音の中で応対 |
| 早口 / 小声 | 5 | 早口 3 件、小声 2 件 |
| 方言 | 5 | 関西・東北など 5 件 |
| 途中切断 | 5 | 会話の途中で切る |

### 記録する KPI

| KPI | 定義 | 目標 |
|--|--|--|
| Call completion rate | 通話が正常に終話した割合 | 95% 以上 |
| False completion | 店員役が確定していないのに `completed` になった件数 | **0** |
| Task success | 「成功」区分で `completed`、それ以外で正しく `incomplete` になった割合 | 90% 以上 |
| Human correction rate | 人が後で結果を直す必要があった割合 | 5% 以下 |
| First response latency | 「もしもし」から AI の最初の発話まで | p50 / p95 / p99 |
| Cost / call | Twilio + モデル | 実測 |
| ASR error | 日付・時刻・人数・名前の誤認識件数 | 実測 |
| Call drop rate | 意図しない切断 | 2% 以下 |

記録先: `docs/launch/real-calls.md`（1 行 1 件: 区分 / 結果 / 期待どおりか / 遅延 / 費用 / 備考）。集計は週次でサイトの数字帯に反映。

### 実施手順

1. `oathra phone doctor --to <本人の番号>` で層ごとの疎通を確認（無料）
2. `oathra phone test --level local`（¥0）で音声エンジンの往復を確認
3. 区分ごとの台本を印刷し、`oathra call --to <本人の番号> --scenario restaurant-reservation` を 1 件ずつ実行
4. 各件の `.oathra/calls/<id>` から結果・遅延・費用を記録し、期待と違う件は `oathra replay` で原因を特定して Issue 化
5. 100 件終了後、KPI 表を README / サイトに載せる（未達の項目は未達のまま載せる）

## 敵対的スイートの拡張（2026-09-13 実施）

### 100 件の区分のうち、シミュレータ（0 円）で確認できたもの

| 区分 | 変異名 | 誤完了 | 完了率（組み込み AI、300 run） | 所見 |
|--|--|--|--|--|
| 留守電 | voicemail | 0 | 0%（正しい） | 留守電の応答文と発信音だけでは何も確定しない |
| 転送 | transfer | 0 | レストラン・シリアル・まとめ買い 100%、**ホテル 0%、英語レストラン 0%** | 「もう一度ご用件を」の後、値切り交渉と英語の流れで組み込み AI が言い直せず諦める（Issue 化） |
| 聞き返し | ask-back | 0 | 同上 | 同上 |
| 保留 | hold-then-reply | 0 | ホテル 63%、英語 42%、他 95〜100% | 「少々お待ちください」を停滞と数えて切る場合がある（Issue 化） |
| 方言 | dialect-confirm | 0 | 100% | 「取っといたで」「合うてるで」を過去形の確定・同意として追加 |
| 拒否・途中切断 | silent-hangup / never-confirm | 0 | 0%（正しい） | 既存 |
| 曖昧・仮押さえ | tentative-hold / never-confirm | 0 | 0%（正しい） | 既存 + 追加 |
| 確定後の訂正・取り消し | confirm-then-change / cancel-after-confirm | 0 | 0%（正しい） | 追加。エンジンの穴 2 つを修正 |

シミュレータで確認できないもの: 騒音、早口・小声、実際の音声認識誤り、遅延の分布、1 通話あたりの費用。ここだけが実電話の役目。

日本語の曖昧表現を中心に 5 種 → 14 種へ。追加: 仮押さえ（一応・後で確認します）、聞き返し（…でよろしいでしょうか？）、確定直後の条件訂正、確定直後の取り消し、保留。拡張で見つかった 2 つの穴（店員の「合っておりますでしょうか？」が同意扱い、「承りました。……やはりお取りできませんでした」が確定扱い）は同日に修正し、10 種で 0 / 10,000。

次の拡張候補（500〜1,000 パターンへ向けて）: 店員の勘違い（別の日付で復唱）、AI 側の勘違い、人数変更、キャンセル依頼、金額の言い間違い、「一応」「念のため」「たぶん」の複合、方言の同意表現。

## L2 に必要なもの（未実装）

Call recording の同意取得と保持期間、電話番号管理とブラックリスト、発信時間帯の制御、通話予算の上限、人間へのエスカレーション、CRM webhook、リトライ方針、レート制限、テナント分離。

## L3 に必要なもの（未着手）

SIP 冗長化と電話会社フォールバック、マルチリージョン、監視と call trace、ページャー、SLO / SLA、PII マスキング、電話関連法令・ガイドライン対応、大量発信制御。
