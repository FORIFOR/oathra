# 実機検証 1件ランブック

## 目的

同意を得た友人の電話番号へ1回だけ発信し、Oathra の Twilio → GPT-Live → 同意付き聞き取り → 保存済み通話記録までが実際に動くことを確認する。店舗や第三者には発信しない。

この1件で判定するのは、設定した経路と1シナリオの実動作である。10件・100件の再現性、SLA、マルチテナント分離、本番運用の安全性は判定対象にしない。

## 固定する検証条件

| 項目 | 値 |
| --- | --- |
| シナリオ | `friend-profile-intake` |
| キャリア | `twilio`（`phone list` で ready を確認済み） |
| 音声エンジン | `gpt-live`（GPT-Live を使用） |
| 宛先 | 同意済みの協力者本人の E.164 番号 `<E164>` |
| 目的 | 友達らしい短い雑談の後、同意を得て非機微な情報を2項目だけ記録 |
| 予算上限 | 発信前に金額を決める。資料上の目安は3分で約110円＋実際のAPI使用料 |
| 記録 | 日時（JST）、通話ID、結果、遅延、費用、エラー、証拠ファイルのパス |

## 発信前（無料の事前確認）

以下は順に実行する。`local` は通話料0円だがモデルAPI使用料が発生する場合がある。`gateway` はLiveKitゲートウェイを使う場合だけ実行する。

```bash
pnpm oathra doctor
pnpm oathra phone list
pnpm oathra phone doctor
pnpm oathra phone test --level local
# LiveKit ゲートウェイ経路も使う構成なら追加
pnpm oathra phone test --level gateway
```

`phone doctor` が `READY` でない場合は発信せず、原因を直してから再実行する。事前確認で宛先に触れる必要がある場合だけ、同意済み番号を使って次を実行する。

```bash
pnpm oathra phone doctor --to <E164>
```

## 協力者への共有事項

発信前に、協力者へ次を伝え、録音・文字起こしへの同意を得る。

1. Oathra の実電話検証であること。
2. 通話音声と文字起こしが検証記録として保存されること。
3. 会話の内容は検証用で、実際のサービス申込みや第三者への連絡には使わないこと。
4. 検証後に記録を削除する方法と、途中で終了できること。

協力者は、発信前に期待結果を手元に書く。今回の期待結果は「短い雑談の後に目的付きの同意を一度確認し、同意後に『最近の関心』と『次回の話題』を各1回だけ聞き、明示回答だけが記録される」で固定する。

## 1回だけの会話スクリプト

協力者は通常の利用者として、次の順序で応答する。余計な条件を追加しない。

1. 近況や最近ハマっていることを、友達との雑談として話す。
2. 同意を尋ねられたら、同意する場合は「いいよ」と明示する。断る場合は「今は答えたくない」と答える。
3. 同意した場合だけ、2つの質問に各1回ずつ答える。機微な情報や、契約にない情報は話さない。
4. 通話後に、協力者側の期待結果と `intake.json` の記録が一致したかを確認する。

## 発信（有料操作はこの1回のみ）

発信直前に、番号・同意・予算上限を再確認する。次のコマンドを1回だけ実行し、失敗しても自動再試行しない。

```bash
pnpm oathra call \
  --to <E164> \
  --scenario friend-profile-intake \
  --engine gpt-live \
  --provider twilio
```

端末に表示された通話ID、開始・終了時刻、終了理由を控える。番号、アクセストークン、音声そのものは外部へ共有しない。

## 合否判定

このシナリオは予約の完了判定を目的にしないため、`result.status` ではなく `intake.json`、`events.jsonl`、`summary.md` の同意・質問・回答イベントを合否の根拠にする。

次のすべてを満たした場合を「1件の実機検証 合格」とする。

- 着信から終了まで接続が維持された。
- 同意前に追加質問をしていない。
- 同意後に宣言済み2項目の明示回答だけが記録された。
- 断り・保留・曖昧な返答があれば、その時点で聞き取りが停止した。
- 通話ID、開始・終了時刻、最終結果、エラー有無を保存できた。
- 協力者の認識と保存された最終結果が一致した。

1つでも満たさない場合は「不合格」とし、同じ番号へ再発信せず、原因を記録する。特に同意前の質問、宣言外の聞き取り、回答の取り違え、途中切断は最優先で確認する。

## 発信後の確認

通話IDを `<CALL_ID>` に置き換えて、保存記録と再生可能な証拠を確認する。

```bash
pnpm oathra replay <CALL_ID>
pnpm oathra replay <CALL_ID> --at mm:ss.mmm
```

文字起こしやログを共有・公開する前に、電話番号、氏名、店舗名などの個人情報を除去する。公開デモやSNSには実通話の音声・全文文字起こしを使わない。

## この1件の限界

合格しても、他の電話番号・騒音環境・失敗シナリオでの品質、10件以上の再現性、企業導入要件のL2/L3達成を意味しない。次の判断には別の試験設計と利用者の同意が必要になる。
