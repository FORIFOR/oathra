# 2026-09-14: a runnable evidence lab, not another launch claim

## Starting point

The repository and bilingual Pages site were already public. GitHub reported 0 stars and 6 views / 6 unique visitors in the available 14-day traffic window. Those are API snapshots, not a causal measure of launch effectiveness. npm still serves 0.1.0; the source tree is 0.1.1 and its GitHub release is a draft.

## Research and decision

Reviewed public community posts and the current product pages on 2026-09-14:

- [Show HN: sub-500ms voice agent](https://news.ycombinator.com/item?id=47224295): a concrete performance result and implementation explanation prompted detailed technical discussion. The retrieved page showed 570 points and 153 comments; this does not predict Oathra's reach.
- [Show HN: self-hosted Asterisk voice agent](https://news.ycombinator.com/item?id=48887276): the audience and infrastructure are explicit; the retrieved page showed 32 points and 11 comments.
- [Open-source WhatsApp voice agent](https://www.reddit.com/r/voiceagents/comments/1ul6dqm/i_built_a_free_opensource_voice_agent_for/): a recognizable task and reproducible flow make scope understandable. This is one example, not evidence of conversion.
- [Pipecat](https://www.pipecat.ai/): places a working example near its entry point. Borrow the principle of immediate trial, not its branding, customer logos or claims.
- [Pipecat benchmarks](https://www.pipecat.ai/benchmarks): explains measurement conditions beside the result. Oathra's simulator counts must not be presented as PSTN reliability.
- [HN guidelines](https://news.ycombinator.com/newsguidelines.html): generated/AI-edited text is disallowed. No automated HN post or attempt to evade the existing account restrictions.

Inference: the most useful next differentiator is a visitor trying to fool the real completion checker, with success *and* retraction visible. A visual redesign alone is unlikely to solve low reach. X search indexing did not provide enough reliable comparison data to call any design “the best.”

## Shipped implementation

- Replace the site's hardcoded result states with the production `EvidenceEngine` and `evaluate`, bundled locally with esbuild.
- Accept the visitor's own text and speaker selection. Escape text with DOM textContent; do not transmit the input.
- Show actual pending/verified field state, including revocation after cancellation.
- Restore warm neutral styling, keep explicit contrast and mobile controls, collapse advanced input behind a disclosure.
- Record Japanese and English browser interactions: 30 seconds each, 4 captured frames/s encoded as 1080p 30fps MP4. The footage shows real engine execution on editable example utterances, not a real phone call. No outcomes were scripted into the UI. Captions are separate WebVTT files; there is no audio.
- Add an L1/L2/L3 scope section and data-flow explanation to both languages. Neither the website nor this release claims a 100-call benchmark or production readiness.
- Fix clipboard feedback so a failed write cannot announce success; remove duplicate playground analytics listeners.

## Validation

- Baseline production build and dependency-direction check passed; existing test suite: 135 passed, 1 live-connection test skipped. Existing tests are not new live-call evidence.
- Website source passes strict TypeScript checking; browser bundle is approximately 88 KB uncompressed.
- Real browser: English hedge → confirmed → retracted flow repeated 10 times, 30 assertions passing. Evidence is in `docs/design/launch-2026-09-14/browser-checks-en.json`.
- Japanese flow and English custom caller-side confirmation verified through actual UI controls. The caller cannot restore a retracted confirmation.
- Japanese/English layouts inspected at 1440px and 390px; screenshots retained. Field Core Web Vitals and human first-impression tests remain unmeasured.
- No PSTN calls were placed in this launch pass. The 10-repeat browser exercise is not the required 100-call evaluation.

## Enterprise gates

The supplied six-product readiness plan is guidance for this repository's L1 presentation. It is not an audit of the other five products. For Oathra, the next real-call campaign must use consented recipients, a defined cost cap, and separately label human-answer, AI-answer over PSTN, and simulator runs. Automated AI-to-AI calls cannot replace human conversational evaluation. Record success, false completion, drop rate, actual carrier/model cost, and p50/p95/p99 response time. An independent expected outcome is required to score false completion; do not use the engine's own completed flag as its ground truth.
