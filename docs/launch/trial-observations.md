# 試用の観察記録（起動・理解・判定のどこで止まるか）

## 2026-09-13 03:50 JST — 自分で初見の経路をなぞった（npm の 0.1.0、空ディレクトリから）

| 段階 | 観察 | 判定 |
|--|--|--|
| 起動 | `npx oathra demo --no-open` で 3 秒で Arena が起動（npx キャッシュあり。初回は npm の取得時間が加わる） | 問題なし |
| 最初の画面 | 「AI同士を見る／自分が電話に出る」の 2 択とシナリオ 7 件。何をするかは分かる | 問題なし |
| Play 開始 | 「自分が電話に出る」→「レストラン予約」で通話画面。店員役が先に話す必要があるが、画面は「発信中…」「聞いています」で、誰が先に話すのか一瞬迷う | 軽微（案内文を 1 行足せば済む） |
| 判定表示 | 挨拶後、AI が「9月12日の19時以降で2名」と依頼。証拠パネルに partySize/date/time が「AI」印つきで未確定として並ぶ | 意図どおり |
| ケース A | 店員役「たぶん大丈夫ですが、まだ確定ではありません。」→ AI「承知しました。では今回は見送らせていただきます。」で通話終了。確定は付かない（誤完了なし）が、**確認を取りに行かずに諦める** | **要修正**。README で勧めている発言で体験が壊れる |
| 通話終了後 | AI の挨拶後も画面は「通話中」のまま入力欄が有効。ケース B を送っても何も起きない | 要修正（終了状態の表示と入力の無効化） |
| 証拠パネル | AI が依頼を言い直すたびに partySize/date/time の未確定エントリが重複して並ぶ（0/6） | 軽微（同一値は 1 行にまとめたい） |

次に変える一点: **曖昧な返答（たぶん・おそらく・確認します）に対して、エージェントが「念のため、確定でよろしいでしょうか？」と確認を求めるようにする。** これがないと、試用の最初の 30 秒で「AI が弱い」という印象になる。

計測の補足: この 1 回は作者本人の操作であり、試用人数には数えない。
