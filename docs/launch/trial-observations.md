# 試用の観察記録（起動・理解・判定のどこで止まるか）

## 2026-09-13 03:50 JST — 自分で初見の経路をなぞった（npm の 0.1.0、空ディレクトリから）

| 段階 | 観察 | 判定 |
|--|--|--|
| 起動 | `npx oathra demo --no-open` で 3 秒で Arena が起動（npx キャッシュあり。初回は npm の取得時間が加わる） | 問題なし |
| 最初の画面 | 「AI同士を見る／自分が電話に出る」の 2 択とシナリオ 7 件。何をするかは分かる | 問題なし |
| Play 開始 | 「自分が電話に出る」→「レストラン予約」で通話画面。店員役が先に話す必要があるが、画面は「発信中…」「聞いています」で、誰が先に話すのか一瞬迷う | 軽微（案内文を 1 行足せば済む） |
| 判定表示 | 挨拶後、AI が「9月12日の19時以降で2名」と依頼。証拠パネルに partySize/date/time が「AI」印つきで未確定として並ぶ | 意図どおり |
| ケース A | 店員役「たぶん大丈夫ですが、まだ確定ではありません。」→ AI「承知しました。では今回は見送らせていただきます。」で通話終了。確定は付かない（誤完了なし）が、**確認を取りに行かずに諦める** | **要修正**。README で勧めている発言で体験が壊れる |
| 通話終了後 | AI の挨拶後も画面は「通話中」のまま入力欄が有効。ケース B を送っても何も起きない | 要修正（終了状態の表示と入力の無効化） |
| 証拠パネル | AI が依頼を言い直すたびに partySize/date/time の未確定エントリが重複して並ぶ（0/6） | 軽微（同一値は 1 行にまとめたい） |

次に変える一点: **曖昧な返答（たぶん・おそらく・確認します）に対して、エージェントが「念のため、確定でよろしいでしょうか？」と確認を求めるようにする。** これがないと、試用の最初の 30 秒で「AI が弱い」という印象になる。

計測の補足: この 1 回は作者本人の操作であり、試用人数には数えない。

## 2026-09-13 05:30 JST — ケース A の修正後（リポジトリ版 Arena で再現）

- 店員役「たぶん大丈夫ですが、まだ確定ではありません。」→ AI「念のため確認させてください。9月12日、19時以降、2名でご予約は確定とさせていただけますでしょうか？」。通話は続き、確定は付かない（誤完了なし）。
- 変更: `providers/simulator/src/agent.ts` に曖昧語（HEDGE_RE）への分岐を追加。確認は最大 2 回、その後は従来どおり。テスト 126 件、`oathra eval` 誤完了 0、敵対的 10,000 run 誤完了 0。Issue #5 を close。
- npm の 0.1.0 にはまだ含まれない（次の publish で反映）。README の「誤完了を誘ってみる」を npx で試す人には、修正前の挙動（見送り）が出る点に注意。
- 未修正: #6（挨拶後も通話中表示）、#7（証拠パネルの重複表示）。
- 補足: 曖昧な返答の後に店員役が「9月12日19時半に2名様でご予約承りました」と、AI がまだ受諾していない 19時半を含めて承諾した場合、確定・日付・人数は検証済みになるが、時刻 19:30 は「相手の提案」として未確定のまま（AI が「では、19時半でお願いします」と受諾し、店員役がもう一度承諾して完了）。順序の厳密さは設計どおりだが、人が店員役をすると「もう承諾したのに」と感じる可能性がある。試用者の反応を見て、UI 側に「AI が受諾した後にもう一度確定してください」の案内を出すか検討する。

## 2026-09-13 05:40 JST — #6（挨拶後も通話中）の原因と修正

- 原因: ランタイムのループが、エージェントが切電を返した後も次の相手発話を待っていた。AI 同士では相手キャラクターが挨拶を返して切るので気づかないが、人が店員役の Play モードでは何も来ず、通話が 20 秒以上開いたままになる。
- 修正: 切電を返した直後にループを抜けて `session.hangup("agent_hangup")` を呼ぶ（`packages/runtime/src/index.ts`）。回帰テストを追加（人の店員役が満席と答えた後、5 秒以内に `agent_hangup` で終了）。テスト 127 件、`oathra eval` 誤完了 0、敵対的 10,000 run 誤完了 0。
- 影響: エージェントが先に挨拶して切る通話の終了理由が `callee_hangup` から `agent_hangup` に変わる。実通話の挙動（挨拶後に自分で切る）と一致する。

## 2026-09-13 05:55 JST — #7（証拠パネルの重複）の修正

- Arena の描画側で、同じ項目・値・話者のエントリを 1 行にまとめる（最新時刻を採用、どれかが検証済みなら検証済み表示）。件数もまとめた後の数。ヘッドレス Chrome の QA（`scripts/qa-arena.mjs`）でページエラーなし、Play 画面は「証拠 0 / 4」で重複なし。
- 試用で見つかった 3 件（#5、#6、#7）はすべて修正済み。npm 0.1.1 の publish 待ち。
