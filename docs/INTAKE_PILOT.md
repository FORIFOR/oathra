# 見積相談の受付・折り返し練習（合成データ専用）

2026-10-05。既存 Oathra Gateway の小さな運用試作です。**本番の受電サービスではありません**。新しい電話・AI・CRM・請求・顧客接続は追加していません。

## 何を確かめるものか

非緊急のリフォーム見積相談を題材に、受付内容を人が確認し、折り返す担当と期限を残し、対応結果まで追えるかを確かめます。需要・価格・売上効果は未検証です。合成会話の項目候補は手で用意しており、AI抽出精度や実際の電話成功率の証拠ではありません。

- 地域、折り返し先、折り返し希望、相談内容を、合成会話の回答と対にして表示
- お客さま役の明示回答だけを候補に採用。AI役、未知の話者、重複した発話ID、本文と一致しない候補は使わない
- 「内容を確認済み」と「折り返しの対応記録済み」は別。見積金額・訪問予約・工事の成立は扱わない
- 例は「回答あり」「折り返し先なし」「話者不明」の3件。実番号、自由な会話、顧客名を入力するAPIは設けない
- 既存アカウントごとに、暗号化SQLiteへ保存。同じ例の再取込は既存記録を返す
- 担当は架空の A / B のみ。通知や電話は送られない。料金は表示・確約しない

## 起動と再現

Node.js 22.13以上、リポジトリの pnpm 環境で:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm demo:app
```

起動時に表示される **ローカル** Oathra の「練習」から「見積相談の受付・折り返しを練習する（合成例）」を選びます。同じサーバーの `/intake-pilot` が入口です。既存のログインを使い、ローカル練習の許可条件も既存Gatewayと共通です。`live` モードでは、このAPIの読取・書込とも拒否します。

1. 「洗面台交換の見積相談」を取り込む。同じ操作を繰り返しても増えない
2. 回答と合成会話を読み、「4項目を人が確認したと記録」を押す。まだ「未対応」
3. デモ担当と30日以内の将来の期限を保存。「折り返し待ちにする」を押す
4. 再読込し、担当・期限・状態が保存されていることを確認する
5. 架空の対応結果を選んで明示的に記録する。電話は一切行われない
6. つながらなかった想定なら「折り返し待ち」のまま、次の期限を保存する。取り消して再確認する場合は「未対応に戻して再確認する」
7. 残りの2例は回答不足なので確認できない。推測で埋めず、要確認のまま残す

期限表示は画面読込・更新時点のものです。自動督促、バックグラウンド監視、共有担当者アカウント、自由入力による不足回答の補完はこの試作にありません。

## 状態と保存の境界

`reviewState: needs_review / confirmed` は人の内容確認記録です。既存 EvidenceEngine の `confirmed` フィールドや Mission の `COMPLETED` とは別物です。新しい商談成立判定は追加していません。

`status: unhandled → callback_pending → done` は業務上の練習状態です。`done` には人の明示操作と許可された結果が必要で、`source: human_demo_report`、`externallyVerified: false` を保存します。通話終了・時間経過・画面アニメーションによる遷移はありません。

担当、期限、確認者、結果、操作履歴を同一トランザクションで保存します。書込失敗は巻き戻し、競合する更新は revision で拒否します。通信切断などで書込成否が不明な画面は、新しい書込を止めて「保存内容を更新」へ誘導します。取込の再試行は同じレコード、更新の再試行は同じ revision の二重適用を拒否する動作です。

保存先は `intake-pilot` レコード種別です。既存の顧客連絡先、通話、ジョブ、クレジットを生成しません。合成記録の保存期間は、この試作から新たに規定していません。ローカル練習用DBの扱いは既存起動設定に従います。実データを入れる機能へ拡張する前に、下記の保存・削除条件を別途決めてください。

## 実顧客に接続する前のゲート

この練習が通っても営業稼働・本番受電開始を意味しません。最低限、次を個別に確定し、実環境で確認する必要があります。

1. 課題確認: 現在の受付方法、件数、折り返し漏れ、担当不在時の引継ぎ、料金に見合う価値。受付代行だけで足りる顧客へ高額プランを前提にしない
2. 対象範囲: 非緊急の見積相談、受付時間、許可された案内、有人担当、緊急・人への接続希望・故障時の扱い。見積金額・施工可否・訪問日を勝手に確約しない
3. 情報の扱い: 送信先、必要項目、AIや記録についての案内、保存場所、アクセス権、保存期間・削除・終了時の扱い。架空の同意方針や保存期間をこの試作から流用しない
4. 接続と検証: 許可された受電入口、元の問い合わせIDによる重複抑止、誤認識時の確認、担当通知と未達、訂正・削除、期限超過のエスカレーション、回復・監査を一貫して確認
5. 原価と契約: 番号、着信/転送、音声認識・合成・LLM、通知、保存・監視、人の確認時間、失敗時の再試行費用を実測。税込/税別、上限、超過、キャンセル、検収条件を確認。現時点の月額原価・販売価格は未確定
6. 稼働判断: 顧客による内容承認と、実回線・データ取扱いの許可を得てから開始。今回のPRではマージ・デプロイ・実発信・顧客への送信をしない

人の確認に要した時間、修正件数、折り返しまでの時間、期限超過数は次の限定検証で測る候補です。合成例の操作時間を実顧客の処理原価や売上改善実績に読み替えないでください。
