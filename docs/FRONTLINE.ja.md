# 現場で使うための設定と範囲（営業・商社・受付・介護）

作成 2026-10-02。Gateway（`apps/gateway`）を業務で使うときに、何ができて、何を人が決め、何がまだ確かめられていないかを業種別にまとめる。設定名は `apps/gateway/.env.example` と同じ。検証の記録は [quality/frontline.md](quality/frontline.md)。

どの業種でも変わらないこと:

- 「決まった」と報告するのは、相手が自分の言葉で確かめた項目だけ。判定は `packages/evidence` の `evaluate()` で、モデルの感想では決めない。
- 発信は人が承認する。定期の電話とリスト発信は、範囲（相手・回数・期限）を見たうえで一度承認する形で、1 件ごとに通常の確認（同意・残高・連絡停止・発信時間帯）を通る。
- AI は最初に AI であることを名乗り、通話の記録を告げる。診断・薬の指示・契約・支払い・値引きの約束はしない。
- 相手が「かけないで」と言えば、その番号には今後かけない。

## 営業・商社

| やりたいこと | 使うもの | 設定・API |
|--|--|--|
| 営業の電話を時間帯の中だけでかける | 発信時間帯 | `OATHRA_SALES_CALL_HOURS`（既定 09:00-20:00、日本時間）。承認時と発信直前の両方で確認 |
| リストに順番にかける | リスト発信 | `POST /v1/batches`（最大 100 件、7 日以内）。かけられない相手と理由は承認の前に示す |
| 連絡先をまとめて登録する | CSV 取り込み | `POST /v1/contacts/import`（最大 500 行、重複は追加しない） |
| 結果を表計算で見る | CSV 出力 | `GET /v1/calls.csv`（自分の分）、`GET /v1/team/calls.csv`（チーム、番号なし） |
| 仕入先に納期・在庫・単価を聞く | テンプレート「納期を確認」「見積・在庫と価格を問い合わせ」 | 通常の依頼。発注・値引き・取消はしない |
| 断られた相手に二度とかけない | 連絡停止 | 営業の電話は「結構です」でも停止。通常の依頼は「もうかけないで」と言われたときだけ停止 |
| 聞き間違いで止まった番号を戻す | 連絡停止の解除 | `POST /v1/suppressions/release`（manager / admin、理由が必須、記録が残る）。相手が自分で 2 を押して止めた番号は解除できない |

営業の電話は冒頭で、会社名、AI がかけていること、案内する商品、営業の電話であることを告げてから話を始める。断られたら引き留めない。

決めること: 発信時間帯、1 日の件数と金額の上限（`OATHRA_DAILY_CALLS` / `OATHRA_DAILY_USD`）、連絡先ごとの「関係」と「連絡する根拠」の記入ルール。

まだないもの: 留守・不在のときの営業の再架電の予約、数量や型番を判定項目にすること（日付・時刻・金額・人数は判定できる）、CRM への自動書き込み（CSV と既存のフォローアップ連携まで）。

## コールセンター・受付

| やりたいこと | 使うもの | 設定 |
|--|--|--|
| 代表番号に社名で出る | 事業者の番号 | `OATHRA_INBOUND_OWNER` `OATHRA_INBOUND_NAME` `OATHRA_INBOUND_BUSINESS=true` |
| 決まった案内だけ AI が答える | 案内事項 | `OATHRA_INBOUND_GUIDANCE_JSON`（30 件まで）。一覧にないことは「確認して折り返します」と言って用件を預かる |
| 「担当者に代わって」と言われたらつなぐ | 人への転送 | `OATHRA_INBOUND_TRANSFER_TO`。つなげなかったら AI が伝言を預かる |
| 受付時間の外は案内だけ流す | 受付時間 | `OATHRA_INBOUND_HOURS` |
| 着信があったことを担当へ知らせる | 通知 | `OATHRA_ALERT_WEBHOOK_URL`（署名つき HTTPS POST） |
| 同時に何本か受ける | 同時通話数 | `OATHRA_MAX_CONCURRENT_CALLS`（既定 1、最大 20） |
| 管理者がチームの通話を見る | チームの電話 | 役割 `manager`。一覧に番号と会話は出ない。記録を開くと監査に残る |
| 飲食店の予約を受ける | 予約受付 | `OATHRA_RESTAURANT_JSON`（台帳が正。既存機能） |

決めること: 案内事項の文面（AI はここに書いたことしか答えない）、転送先の番号、同時通話数（電話会社の同時通話枠と音声モデルの利用上限を先に確認する）。

まだないもの: 番号ごとに別の事業者として出ること（1 つの Gateway は 1 つの着信設定）、待ち呼（すべて通話中なら案内して切る）、従量課金の契約での転送、プッシュ番号によるメニュー、応答率などの集計画面。

## 介護施設・見守り

| やりたいこと | 使うもの | 設定・API |
|--|--|--|
| ゆっくり、やさしい言葉で話す | 話し方「ゆっくり・やさしく」 | 依頼に `pace: "gentle"`。短い文、一度に一つ、聞き返しに何度でも答える。沈黙の待ち時間も長くなる |
| 毎日決まった時刻にかける | 定期の電話 | `POST /v1/schedules`（時刻・曜日・終了日は 92 日以内・不在時の再架電 0〜3 回）。登録済みの連絡先だけ |
| 体調・食事・服薬・睡眠・困りごとを聞いて記録する | 見守りテンプレートと聞き取り結果 | 報告に、項目ごとの答えと本人の言葉が並ぶ。あいまいな答えは「要確認」 |
| 不調や危険を示す言葉があったらすぐ知らせる | 要確認の通知 | 「助けて」「胸が痛い」「転んだ」などを相手の発言から検出し、通話中に通知。通話は切らない |
| 出なかったら知らせる | 不応答の通知 | 再架電を使い切って誰も出なければ通知 |
| ご家族へ面会や予定を知らせる | テンプレート「ご家族へ面会・予定の連絡」 | 体調や医療の質問には答えず担当者へ |

AI がすること・しないこと:

- 体の不調や危険を聞いたら、用件を止めて受け止め、119 番（事件は 110 番）か近くの人・職員を呼ぶよう伝える。AI は救急車も人も呼べない。呼んだかのような言い方はしない。
- 診断、病名の推測、薬の種類や量の指示はしない。
- 聞き取り結果は「本人がそう話した」という記録で、事実の確認ではない。「飲んだ」と話したことと、飲んだことは別。
- 検出する言葉は広めに取ってある。見逃しを減らすためで、通知が来ても何も起きていないことはある。逆に、言葉にならない異変は検出できない。

決めること: 誰が同意したか（本人・ご家族）、通知を誰がいつまでに見るか、通知に会話の文面を載せるか（`OATHRA_ALERT_INCLUDE_QUOTES`。既定は載せない。健康に関する情報のため）、保存期間（`OATHRA_RETENTION_DAYS`）。

まだないもの: 入居者ごとの推移の画面、ご家族への自動の報告、施設単位の入居者管理（連絡先と定期の電話で代用する）。**この電話は見守りの補助で、安否確認や緊急通報の代わりにはならない。**

## 通知の形式

`OATHRA_ALERT_WEBHOOK_URL` へ、次の JSON を HTTPS で POST する。

```json
{ "type": "oathra.alert", "version": 1, "id": "<通話ID>:distress:emergency", "reason": "distress",
  "level": "emergency", "mission": "<通話ID>", "recipient": "山田 花子", "at": "2026-10-02T00:10:00.000Z",
  "categories": ["breathing", "pain"], "message": "【要確認】…", "reportUrl": "https://…/app/#/call/<通話ID>" }
```

- `reason`: `distress`（発言）、`unanswered`（不応答）、`checkin`（聞き取り結果）、`schedule`（定期の電話を発信できなかった）、`batch`（リスト発信を一時停止した）、`inbound`（着信に応対した）。
- `level`: `emergency` / `concern` / `notice`。
- 署名: ヘッダー `x-oathra-signature: t=<秒>,v1=<HMAC-SHA256("<t>.<本文>") の16進>`。秘密は `OATHRA_ALERT_WEBHOOK_SECRET`。
- 失敗した配信は最大 5 回まで間隔を空けて再送する。同じ通話・理由・レベルの通知は 1 回だけ。

## 運用

- 停止（デプロイ）: SIGTERM で新しい通話を受けるのをやめ、通話中の電話が終わるのを待つ（`OATHRA_SHUTDOWN_GRACE_SECONDS`、既定 330 秒）。
- バックアップ: `node --env-file=<env> apps/gateway/backup.mjs <新しいディレクトリ>`。
- 復元: Gateway を止めてから `node --env-file=<env> apps/gateway/restore.mjs <バックアップ>`。既存の DB は上書きしない。データ鍵（`OATHRA_DATA_KEY`）はバックアップに入っていないので、別に保管する。
- 役割: `admin`（運用者）、`manager`（自分のチームの通話を見る）、`operator`、`viewer`、`agent`。

## 使い始める前に確かめること

自動テストは、判定・通知・承認・上限が決めたとおりに動くことを確かめている。**実際の電話で、相手にどう聞こえるかは確かめていない。** 現場に出す前に、自分たちの番号で次を試す。

1. 高齢の方役に、ゆっくり・小声・聞き返しを含めて 10 件。途中で割り込まれないか、切られないか。
2. 「胸が痛い」「転んだ」と言って、通知が届くまでの秒数と、AI の受け答え。
3. 代表番号に、案内事項にある質問とない質問を 10 件ずつ。ない質問に勝手に答えないか。
4. 「担当者に代わって」で転送されるか。転送先が出ないときに伝言へ戻るか。
5. 営業の電話の冒頭が、会社名・AI・商品・営業の順で言えているか。断ったあと引き留めないか。
6. 同時通話数を上げるなら、その本数を同時にかけて音切れと遅延を測る。

費用と件数の考え方は [READINESS.md](READINESS.md) の実電話 100 件の計画と同じ。
