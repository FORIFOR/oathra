# Design brief — Gateway ワークスペース

2026-09-20 managed電話画面の追加方針: 既存Arenaの配置を保ち、必須3入力→確認dialog→「同意して電話する」に簡略化。費用・送信先・保存・不可逆性の説明とサーバーの明示承認を維持し、独立した同意checkboxは最終ボタンへ統合する（以下の旧営業画面のcheckboxは変更しない）。認証はメール/パスワードと8時間のHttpOnlyセッション。初回は個別の期限付きリンクで既存ownerに登録、通常の入力欄は2つ。「アカウント」dialogからパスワード変更。管理者向けトークン操作は一般UIに出さない。未接続時は発信と称さず下書き保存まで。通常利用者にAPIキーや公開接続の設定を求めない。

| 項目 | 内容 |
|---|---|
| 製品 / 画面 | Oathra Gateway（apps/gateway/public）。電話を任せて、結果を受け取る1枚の画面 |
| 対象種別 | web-app（同じAPIを apps/ios とLINE・Slackも使う） |
| 対象ユーザー | 電話業務を任せたい担当者。開発者ではない。APIやフィールド名を知らない |
| 利用者が完了したい1つの仕事 | 「だれに、なにを」を伝えて、相手が本当に了承したことだけを受け取る |
| 初見で分かってほしいこと | 承認するまで電話はかからない。決まったことと、まだ決まっていないことは分けて出る |
| 最重要の操作と結果 | 相手・商品・目的を選ぶ → 内容を確認 → チェックして承認 → 進行 → ふつうの言葉の結果と、根拠になった相手の発言 |
| 今回変えないもの | API、承認の安全策（確認ダイアログとチェック）、CSP（textContentのみ、インラインなし）、練習モードが既定 |
| 想定する画面幅・言語・入力方法 | 1280×800〜1920×1080のノートPCでスクロールなし。390pxでは縦積み。日本語。マウスとタッチ |
| 利用できる部品・トークン | docs/design/ui/tokens.md。ネイティブの select / details / dialog を使う |
| 説明なしでも理解できる入口 | サインインの「トークンはどこにありますか？」、上の「はじめに あと○つ」、右の空状態の3ステップ |
| この製品らしい表現1つ | 結果を「確認できたこと ✓ / まだ決まっていないこと … / 根拠になった相手の言葉」に分けて見せる |
| 今回採用しない表現と理由 | タブやページ遷移（利用者が「1枚で」と明示）。英語の飾り見出し、内部キーやエラーコードの表示（誰でも使える、に反する）。（暗い配色は2026-09-12に一度却下されたが、2026-09-28の UI v2 で利用者が既定に変更した。下記） |
| 承認済み / 提案段階 | 盤面レイアウトは 2026-09-19 に利用者の指示で実装・マージ済み（PR #33、#34）。利用者による初見テストは未実施 |

## 利用者から実際に出た指摘（2026-09-19）
- トークンに何を入れるのか分からない → サインインに案内を追加。
- `phone_verification_not_configured` がそのまま出た → 使えない機能は出さずに説明、エラーは文で出す。
- 縦に長い1列は「1枚にまとまった」ではない → ウィンドウに収まる盤面へ。

## UI v2（2026-09-28）

利用者が渡した設計（design_handoff_oathra_ui_v2 §3）に沿って見た目を揃える。利用者の判断：暗い配色を既定にし、明るい配色も選べるように残す（`?theme=light`、ブラウザに記憶）。Arena の次に Gateway。

- 画面の構成・ID・文言の意味・操作の順番は変えない（テストが守る導線はそのまま）。変えるのは階層の付け方：塗りと影をやめ、文字の太さと1pxの線で分ける。
- ヘッダー：ロゴの印と「oathra」、右に練習/本番の状態・設定・ログアウトを文字リンクで。
- 目的の選択：枠つきの縦のラジオ一覧。選んだ行だけ説明を右に出す（幅1000px以上）。狭い画面では従来どおり一覧の下に一度だけ出す。
- 結果：見出し（決まりました など）の上に相手と時刻、下に「頼んだこと」。その下は左に項目名・右に内容の定義リスト（確認できたこと／根拠になった言葉／まだのこと）。根拠は相手の言葉をそのまま大きく。
- 幅1000px以上は 480px | 残り の2列で、カードの枠を消して1枚の紙のように読む（明るい配色でも同じ）。狭い画面は従来どおりカードを縦に。
- 管理型の電話ページ（`phone/`）の確認画面：音声AIは既定と違うときだけ「通話の長さ・声」の行に名前で添える（モデルIDは出さない）。行を増やすと同意する内容が最初の画面から押し出されるため。
- 目的に「雑談する」（2026-09-28）：商品と「自分にかけて試す」を隠し、声（標準／演技する声・女性／男性）を出す。中身は管理型の電話ページと同じ自由な依頼（雑談モード）。練習モードでは発信できないので、確認画面で先にそう伝えて承認ボタンを押せなくする。
- 「電話で名乗る名前」を設定に置き、はじめにの手順にも出す。利用者ごとに保存し、確認画面に「名乗る名前」として出す（どの利用者でも自分の名前で電話できるように）。

## Ring Zero テーマ（2026-09-29）

利用者が渡したパッチ（oathra-ringzero-patch）を反映。明るい配色を既定にする（`<html data-theme="light">`）。暗い配色は `?theme=dark` で選べ、ブラウザに記憶する（2026-09-28 の「暗い配色を既定」はこれで置き換え）。地は Mist `#F1F4F2`、面は白、文字とボタンは墨 `#0E1512`。Oath Jade `#0B7A58` はロゴと「相手の言葉で確認済み」だけ（ボタンやAIの発言には使わない）。要確認は琥珀、通話中・切断はコーラル。書体は IBM Plex Sans JP / Mono を指定し、読み込みはしない（外部通信なし。手元の書体で代わりに表示）。Arena の判定欄は、確かめる項目の数だけ区切った輪が、相手の言葉で確かめられるたびに閉じていく（`ringzero.js`、表示だけ）。判定する項目がない本番の電話では輪を出さない。管理型の電話ページは従来の見た目のまま。

## 新しい画面（Oathra App、2026-09-29）

利用者のデザイン「Oathra App.dc.html」を、今あるAPIで作った。利用者の判断：/app で作り、そろったら / と置き換える（完了。セルフホストの `/` は新しい画面、従来の画面は `/workspace`。管理型の `/` は従来の電話ページのまま）。営業の目的は「電話を頼む」に組み込む。

- 画面：ホーム・依頼（確認が必要／進行中／完了）・電話を頼む・電話中と報告（輪は証拠エンジンの確認済みだけで閉じる）・練習（組み込みの相手と、このサーバーで。電話も費用もなし）・連絡先・設定。
- 電話を頼む：目的は「依頼（ふだんの言葉で）・雑談・商談の日時を決める・資料を送ってよいか聞く・商品を説明する」。営業の目的は、関係と根拠のある連絡先と、確認済みの商品が必要（設定の「商品」、連絡先の「関係」「根拠」）。練習モードでは営業の電話は練習用の相手と話す。
- まだないもの（画面でそう書く）：任せる範囲（○△×）、AIが判断したこと、利用者ごとの着信設定、月の上限、円の費用グラフ、アプリ内の「自分が相手役」（Arenaを案内）。連携・転送・番号確認・連絡停止は従来の画面にある。
- 任せる範囲・AIが判断したこと・着信の設定・月の上限（2026-09-29、利用者の判断で追加）：
  - 任せる範囲は利用者のパッチどおり、依頼文の【任せる範囲】として送る（スキーマ変更なし）。
  - AIが判断したこと：GPT-Live と Gemini Live に record_decision の道具を持たせ（「その場で決めてよい」がある依頼だけ）、報告に「AIの報告です」と明記して並べる。判定（決まったか）には使わない。演技する声（文字のAI）はまだ記録しない。
  - かけられた時の設定：受け方（AIが用件を聞く／あなたにつなぐ／出ない）・受ける時間・名乗る名前を利用者ごとに保存。受けるかどうかと番号の持ち主は管理者の設定のまま。「あなたにつなぐ」は確認済みの番号があり、クレジット制でないときだけ。
  - 月の上限：承認時に、今月承認した電話の見込み上限の合計＋この電話の見込みで止める（日本時間の月）。
- ログイン（2026-09-29、利用者の判断）：画面のログインはメールアドレスとパスワード。トークンは管理者用（API・SDK・初期設定）として「管理者のトークンでログイン」に残す。自分のメールログインは 設定 › 記録と表示 から1回限りのリンクで設定する。`OATHRA_LOCAL_OPEN=true` のときだけ、simulator モードで、このパソコンから localhost に開いた場合はログインを省く（書き込みは同じ画面からに限る）。
