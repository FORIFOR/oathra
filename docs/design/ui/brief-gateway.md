# Design brief — Gateway ワークスペース

## 2026-10-02: アプリ全体への品質目標の適用

ユーザーが「アプリ全体を対象にする」と指定した。公開入口だけでなく、ホーム、依頼準備、報告・履歴、予定・練習、連絡先、設定、アカウントとクレジットを同じ基準で扱う。[観測・修正・検証範囲](../../quality/app-craft.md)を参照。以下の旧画面向け「1枚」の方針は履歴であり、現在の複数画面を作り直して1枚へ戻す指示ではない。

- ホームは最新の報告を主列、発信の状態・残高・当月の依頼を補助列にする。失敗した依頼を成功件数に見せない。
- 停止中という事実は常時示し、詳細な上限だけを開いて読める構成にする。受け付けられない発信を可能と表示しない。
- 狭幅でもすべての主メニューと依頼日時を読めること。設定の目次だけで最初の画面を占有しない。長い依頼文は報告の結論と会話より優先しない。
- 残高、確保中、購入履歴、利用履歴を区別する。空履歴・取得中・通信失敗を別の状態として示す。dialogを閉じる操作をスクロール先へ追いやらない。
- 色・字体は下記のRing Zeroを継続。ラベル・ネイティブ操作・フォーカスを保持し、動きや飾りの成果を増やすことを品質改善と扱わない。
- ログイン状態とアカウントの境界を画面間で維持する。費用、相手、任せる範囲、同意の確認を省略しない。

2026-09-20 managed電話画面の追加方針: 既存Arenaの配置を保ち、必須3入力→確認dialog→「同意して電話する」に簡略化。費用・送信先・保存・不可逆性の説明とサーバーの明示承認を維持し、独立した同意checkboxは最終ボタンへ統合する（以下の旧営業画面のcheckboxは変更しない）。認証はメール/パスワードと8時間のHttpOnlyセッション。初回は個別の期限付きリンクで既存ownerに登録、通常の入力欄は2つ。「アカウント」dialogからパスワード変更。管理者向けトークン操作は一般UIに出さない。未接続時は発信と称さず下書き保存まで。通常利用者にAPIキーや公開接続の設定を求めない。

## UI v2（2026-09-28）

利用者が渡した設計（design_handoff_oathra_ui_v2 §3）に沿って見た目を揃える。利用者の判断：暗い配色を既定にし、明るい配色も選べるように残す（`?theme=light`、ブラウザに記憶）。Arena の次に Gateway。

- 画面の構成・ID・文言の意味・操作の順番は変えない（テストが守る導線はそのまま）。変えるのは階層の付け方：塗りと影をやめ、文字の太さと1pxの線で分ける。
- ヘッダー：ロゴの印と「oathra」、右に練習/本番の状態・設定・ログアウトを文字リンクで。
- 目的の選択：枠つきの縦のラジオ一覧。選んだ行だけ説明を右に出す（幅1000px以上）。狭い画面では従来どおり一覧の下に一度だけ出す。
- 結果：見出し（決まりました など）の上に相手と時刻、下に「頼んだこと」。その下は左に項目名・右に内容の定義リスト（確認できたこと／根拠になった言葉／まだのこと）。根拠は相手の言葉をそのまま大きく。
- 幅1000px以上は 480px | 残り の2列で、カードの枠を消して1枚の紙のように読む（明るい配色でも同じ）。狭い画面は従来どおりカードを縦に。
- 管理型の電話ページ（`phone/`）の確認画面：音声AIは既定と違うときだけ「通話の長さ・声」の行に名前で添える（モデルIDは出さない）。行を増やすと同意する内容が最初の画面から押し出されるため。
- 目的に「雑談する」（2026-09-28）：商品と「自分にかけて試す」を隠し、声（標準／演技する声・女性／男性）を出す。中身は管理型の電話ページと同じ自由な依頼（雑談モード）。練習モードでは発信できないので、確認画面で先にそう伝えて承認ボタンを押せなくする。
- 「電話で名乗る名前」を設定に置き、はじめにの手順にも出す。利用者ごとに保存し、確認画面に「名乗る名前」として出す（どの利用者でも自分の名前で電話できるように）。

## Ring Zero テーマ（2026-09-29）

利用者が渡したパッチ（oathra-ringzero-patch）を反映。明るい配色を既定にする（`<html data-theme="light">`）。暗い配色は `?theme=dark` で選べ、ブラウザに記憶する（2026-09-28 の「暗い配色を既定」はこれで置き換え）。地は Mist `#F1F4F2`、面は白、文字とボタンは墨 `#0E1512`。Oath Jade `#0B7A58` はロゴと「相手の言葉で確認済み」だけ（ボタンやAIの発言には使わない）。要確認は琥珀、通話中・切断はコーラル。書体は IBM Plex Sans JP / Mono を指定し、読み込みはしない（外部通信なし。手元の書体で代わりに表示）。Arena の判定欄は、確かめる項目の数だけ区切った輪が、相手の言葉で確かめられるたびに閉じていく（`ringzero.js`、表示だけ）。判定する項目がない本番の電話では輪を出さない。管理型の電話ページは従来の見た目のまま。

## 新しい画面（Oathra App、2026-09-29）

2026-10-02 の品質改善: 公開サイトから Gateway のログイン・AI連携まで、Ring Zero の明るい背景・墨色の操作・証拠の Jade を基準に整えた。未ログインの `/` と `/app/` は同じ価値説明と公開ログ検証・`/connect` の入口を持ち、狭幅ではフォームより先に入口を出す。停止の事実は常時表示し、利用上限と着信条件は開閉できる詳細へ。`/connect` は接続準備を先に読み、Claude Code と ChatGPT を選択する。OAuth の許可と電話の確認では設定案内を隠し、その判断に集中できる構成にする。通常の電話操作・個別発信の同意・公開停止の契約は変更しない。[審査観点・反復レビュー・実画面証拠](../../quality/award-craft.md)。受賞と一般公開の完了は別に評価する。

利用者のデザイン「Oathra App.dc.html」を、今あるAPIで作った。利用者の判断：/app で作り、そろったら / と置き換える（完了。セルフホストの `/` は新しい画面、従来の画面は `/workspace`。管理型の `/` は従来の電話ページのまま）。営業の目的は「電話を頼む」に組み込む。

- 画面：ホーム・依頼（確認が必要／進行中／完了）・電話を頼む・電話中と報告（輪は証拠エンジンの確認済みだけで閉じる）・練習（組み込みの相手と、このサーバーで。電話も費用もなし）・連絡先・設定。
- 電話を頼む：目的は「依頼（ふだんの言葉で）・雑談・商談の日時を決める・資料を送ってよいか聞く・商品を説明する」。営業の目的は、関係と根拠のある連絡先と、確認済みの商品が必要（設定の「商品」、連絡先の「関係」「根拠」）。練習モードでは営業の電話は練習用の相手と話す。
- まだないもの（画面でそう書く）：任せる範囲（○△×）、AIが判断したこと、利用者ごとの着信設定、月の上限、円の費用グラフ、アプリ内の「自分が相手役」（Arenaを案内）。連携・転送・番号確認・連絡停止は従来の画面にある。
- 任せる範囲・AIが判断したこと・着信の設定・月の上限（2026-09-29、利用者の判断で追加）：
  - 任せる範囲は利用者のパッチどおり、依頼文の【任せる範囲】として送る（スキーマ変更なし）。
  - AIが判断したこと：GPT-Live と Gemini Live に record_decision の道具を持たせ（「その場で決めてよい」がある依頼だけ）、報告に「AIの報告です」と明記して並べる。判定（決まったか）には使わない。演技する声（文字のAI）はまだ記録しない。
  - かけられた時の設定：受け方（AIが用件を聞く／あなたにつなぐ／出ない）・受ける時間・名乗る名前を利用者ごとに保存。受けるかどうかと番号の持ち主は管理者の設定のまま。「あなたにつなぐ」は確認済みの番号があり、クレジット制でないときだけ。
  - 月の上限：承認時に、今月承認した電話の見込み上限の合計＋この電話の見込みで止める（日本時間の月）。
- ログイン（2026-09-29、利用者の判断）：画面のログインはメールアドレスとパスワード。トークンは管理者用（API・SDK・初期設定）として「管理者のトークンでログイン」に残す。自分のメールログインは 設定 › 記録と表示 から1回限りのリンクで設定する。`OATHRA_LOCAL_OPEN=true` のときだけ、simulator モードで、このパソコンから localhost に開いた場合はログインを省く（書き込みは同じ画面からに限る）。
- Arena の統合・段階1（2026-09-29、利用者の承認）：練習の「自分が相手役」を Gateway に移した（AIが電話をかけ、利用者がお店として文字で答える。判定は evidence のまま、決まった項目の引用は相手＝利用者の言葉だけ）。声の見本は 設定 › 声とAI と「電話を頼む」の声の横で聞ける。`pnpm demo:app` で設定なしの練習用 Gateway（simulator・localhost のみログインなし）。`npx oathra demo`（npm 配布）はまだ Arena のまま：Gateway を CLI パッケージに同梱するまで Arena は外さない。
- Arena の統合・段階2（2026-09-29、利用者の承認）：Gateway を CLI の npm パッケージに同梱（`dist/bundle/gateway.js` と `assets/gateway-root`。実行時に読むファイルは `apps/gateway/lib/paths.mjs` の `repoUrl` を通す）。`oathra demo` は Gateway を練習モードで開く。Arena は `--arena` と、Arena だけの機能（`--tunnel` `--allow-remote` `--allow-models`、ローカルの Web 発信）のために残す。Arena の削除は、これらを Gateway に移してから。
- Arena の統合・段階3（2026-09-29、利用者の判断「別の端末からは開けるように」「全て取り入れて」）：`oathra demo` に `--allow-remote`（LAN。起動時のログイン用リンク `#token=` で入る。このパソコンだけはログイン不要）、`--tunnel`、`--allow-models`（練習で電話するAIを選ぶ。外部AIは送信と料金を画面で明示）、`--live --tunnel`（このパソコンのキーで実際の電話）を移した。練習の記録（この画面の練習と `oathra play`）は `.oathra/calls/` に保存し、練習画面の「記録」で見返す。スマホ幅で上のタブが1文字ずつ折り返していたのを1行にした。
- Arena の削除（2026-09-29、利用者の承認）：apps/arena と Arena 専用のテスト・スクリプト・CI を削除。管理運用モード（managed）の画面が使う HTML/CSS は `apps/gateway/public/phone/base/` に移した。動画のスクリプト（capture-demo・render-video・render-battle2 + video/battle2.html）はアプリの練習と「記録」（`oathra.seek` で任意の時点へ）を撮るように直した。撮り直しは未実施。

## 見守り・定期の電話・チーム・連絡先の取り込み（2026-10-02）

サーバーにあって画面のなかった機能を、既存の部品と文言の調子で足した。新しい主要画面の案出しはしていない（既存の一覧・報告・確認欄の展開。推定で、利用者の承認は未取得）。

- 電話を頼む：種類に「見守り・介護」「取引先への確認」。「ゆっくり・やさしく話す」は見守りとお薬の声かけで自動的にオン、確認欄に「話す速さ」として出す。
- 報告：`attention` があれば見出しより上に帯を出す。緊急と要確認は言葉・「!」・塗りで分け、該当する発言を引用し、「診断ではない・AIは助けを呼んでいない」を固定で添える。見守りの聞き取りは「〜と話しました」の表（事実として書かない）。応答なしは見出しと注意書きで示す。見守りの電話では、記憶が推測しただけの日付を「決まりませんでした」の判定に使わない。
- 定期の電話（`#/standing`、入口は依頼）：確認欄の「定期の電話にする」から。連絡先に保存し根拠が書かれた相手だけ、予約と営業は不可。決まりと回数の上限を読んでチェックしてから登録。一覧で一時停止・再開・終了。
- チームの電話（`#/team`、manager と admin だけに入口）：一覧に電話番号と会話は出さない。要確認だけの絞り込み、CSV、相手の名前から読むだけの報告。
- 連絡先：連絡停止中の表示と、理由を書いての解除（manager・admin）。CSVの取り込み（UTF-8 のみ、500件まで、取り込めなかった行は理由つき）。電話の記録のCSVは依頼の画面に置いた。
- まだないもの：チームの集計（`/v1/team/summary`）、名簿への一斉発信、定期の電話の内容の変更（終了して登録し直す）。

### 第2回（2026-10-02、独立レビューの指摘と追加画面）

- 報告の帯は「ご本人の様子を確かめてください」と人の確認を求め、「AIはどこにも連絡していません。」を本文の太さと色で独立した行にする。同じ発言は帯・聞き取りの表・会話で同じ段階（緊急／要確認）を示す。見出しの上に通話の日時（日本時間）、定期の電話は何回目かとかけ直しの有無。
- チームの電話：結果は通話の言葉（話せました／応答なし／かけられませんでした）で、見守りの電話に「確認済み」は使わない。応答なしは「×」つきの印と左の帯。聞き取りは「〜と話した」。上に「この7日間」（件数、応答率とその母数、要確認、緊急、日ごと）。
- 定期の電話：回数の上限は選んだ曜日だけを数え内訳を出す。承認の直前に、相手・時刻・曜日・いつまで・上限・出ないとき・止め方をまとめ、欄の中でスクロールさせない。夜間の時刻と通知先のない見守りは、登録前に断る。
- 連絡停止：ご本人が通話中に止めた場合は解除の入力欄を出さず、最初から解除できないと書く。
- 名簿にまとめて電話（`#/lists/new`、一覧は `#/lists`）：連絡先で相手を選び、内容を一度決め、かける相手・かけない相手と理由・決まりを読んで承認する。かけない相手は画面で連絡先の項目から同じ決まりで出し、登録時にサーバーがもう一度決める。
- 見守りの種類では、依頼文の施設名を「だれの代わりか」として一つだけ名乗る。ひな形の（施設名や依頼者の名前）が文に残ったままでは確認に進めない。確認欄にモデル名は出さない。

### 第3回（2026-10-02、2回目の独立レビュー）

- 報告の帯の決まり（自分の報告もチームの報告も同じ）：帯は印のついた発言を引用し、表にだけある要確認は「ほかに要確認がN件あります（下の表）」と数える。印のついた発言がなくても、表に要確認があれば要確認の帯を出す。応答のなかった見守りの電話も同じ帯の形で、何回目の電話かを書く。
- 名簿：進み具合は「かける相手のうち何人にかけ終えたか」。かけない相手は数に入れない。確認欄はサーバーの事前確認（`/v1/batches/preview`）の結果を出し、最大の回数と、いつからかけ始めるか、実際の時間帯を書く。
- 定期の電話の回数の上限は、これから先に来る時刻だけを数える（サーバーの `occurrences` と同じ数え方）。
- チームの「この7日間」：応答の割合は、応答が記録された電話だけを母数にしてそう書く。応答なしの件数、要確認（うち緊急）を並べる。
- 連絡停止：いつ・どうやって止まったかを、サーバーの記録から書く（だれが止めたかは記録がないので書かない）。解除したあとは、解除したことと理由が記録されたことを連絡先に出す（この表示は開いている間だけ。解除の履歴を返すAPIはない）。
- 確認欄は欄の中でスクロールさせない。音声AIの行は、サーバーの既定と違うものを選んだときだけ、製品IDなしで出す。
