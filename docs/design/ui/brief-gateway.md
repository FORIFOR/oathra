# Design brief — Gateway ワークスペース

| 項目 | 内容 |
|---|---|
| 製品 / 画面 | Oathra Gateway（apps/gateway/public）。電話を任せて、結果を受け取る1枚の画面 |
| 対象種別 | web-app（同じAPIを apps/ios とLINE・Slackも使う） |
| 対象ユーザー | 電話業務を任せたい担当者。開発者ではない。APIやフィールド名を知らない |
| 利用者が完了したい1つの仕事 | 「だれに、なにを」を伝えて、相手が本当に了承したことだけを受け取る |
| 初見で分かってほしいこと | 承認するまで電話はかからない。決まったことと、まだ決まっていないことは分けて出る |
| 最重要の操作と結果 | 相手・商品・目的を選ぶ → 内容を確認 → チェックして承認 → 進行 → ふつうの言葉の結果と、根拠になった相手の発言 |
| 今回変えないもの | API、承認の安全策（確認ダイアログとチェック）、CSP（textContentのみ、インラインなし）、練習モードが既定 |
| 想定する画面幅・言語・入力方法 | 1280×800〜1920×1080のノートPCでスクロールなし。390pxでは縦積み。日本語。マウスとタッチ |
| 利用できる部品・トークン | docs/design/ui/tokens.md。ネイティブの select / details / dialog を使う |
| 説明なしでも理解できる入口 | サインインの「トークンはどこにありますか？」、上の「はじめに あと○つ」、右の空状態の3ステップ |
| この製品らしい表現1つ | 結果を「確認できたこと ✓ / まだ決まっていないこと … / 根拠になった相手の言葉」に分けて見せる |
| 今回採用しない表現と理由 | タブやページ遷移（利用者が「1枚で」と明示）。英語の飾り見出し、内部キーやエラーコードの表示（誰でも使える、に反する）。暗い配色（2026-09-12に却下済み） |
| 承認済み / 提案段階 | 盤面レイアウトは 2026-09-19 に利用者の指示で実装・マージ済み（PR #33、#34）。利用者による初見テストは未実施 |

## 利用者から実際に出た指摘（2026-09-19）
- トークンに何を入れるのか分からない → サインインに案内を追加。
- `phone_verification_not_configured` がそのまま出た → 使えない機能は出さずに説明、エラーは文で出す。
- 縦に長い1列は「1枚にまとまった」ではない → ウィンドウに収まる盤面へ。
