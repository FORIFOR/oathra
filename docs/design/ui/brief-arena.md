# Design brief — Arena

| 項目 | 内容 |
|---|---|
| 製品 / 画面 | Oathra Arena（apps/arena/public）。`oathra demo` で開く、通話を見る・自分が出る画面 |
| 対象種別 | web-app（ローカルのデモ。録画用に `?present=1`） |
| 対象ユーザー | 音声・電話AIを作る開発者と、製品を初めて見る人 |
| 利用者が完了したい1つの仕事 | 電話を1本選び、AIと相手の会話と、相手の発言から証拠が確定していく様子を見る |
| 初見で分かってほしいこと | AIが「できました」と言っても完了にならない。相手が言ったときだけ ✓ が付く |
| 最重要の操作と結果 | 左でミッションを選ぶ → 中央で通話が始まる → 文字起こしの横で証拠が確定 → 証拠の上に結果カード（広い画面）。狭い画面では同じ順に縦へ積む |
| 今回変えないもの | scripts/verify-evidence-workspace.py が使う要素ID、style-base.css（ハッシュ固定）、`?present=1` の1画面表示、orbのアバター |
| 想定する画面幅・言語・入力方法 | 1440×900、1280×800、390×844。幅1100px以上かつ高さ600px以上は盤面（ページはスクロールしない）、それ未満は縦に積む。日本語 / 英語、ライト / ダーク |
| 利用できる部品・トークン | apps/arena/public/style-base.css。レイアウトの上書きは one-page.css（積む）と board.css（盤面） |
| 説明なしでも理解できる入口 | 左の一覧の見出し「電話を選ぶと、すぐ始まります。」と、空の中央に出る「左から電話を選ぶと、ここで始まります。」 |
| この製品らしい表現1つ | 文字起こしの隣で、相手の発言が証拠カードとして未確定→検証済みに変わる |
| 今回採用しない表現と理由 | 画面の切り替え（利用者が「1枚で」と明示）。~~暗い既定配色（却下済み）~~ → 2026-09-28 に利用者が UI v2（暗い既定・明るい配色も選択可）を採用。下の「UI v2」を参照 |
| 承認済み / 提案段階 | 画面を積む構成は PR #33 で実装済み。盤面（A案）は 2026-09-19 に3案を実画面で比べて実装者が選んだもの。利用者の承認はまだ（「1枚＝ウィンドウに収まる盤面」という要望には沿う） |

## 盤面の構成を選んだ経緯（2026-09-19）
終わった実通話（friend-hype）に3つの構成を当て、1440×900で撮って比べた。色や部品は同じで、置き方だけが違う。

| 案 | 構成 | 判断 |
|---|---|---|
| A | 左にミッションの列、中央に通話、右に結果と証拠 | **採用。** 8個のミッションが横スクロールなしで全部見える。通話前は中央が「ここで始まる」場所になる。文字起こしの隣に証拠、というこの製品らしい表現が残る。Gatewayの盤面（左で選ぶ・右で起きる）と同じ型 |
| B | 上にミッションの帯、左に通話、右に結果と証拠 | 不採用。帯は横スクロールになり、名前が隠れる。通話前の画面がほぼ空になる |
| C | 上に帯、文字起こしを広く、証拠は下に横並び | 不採用。証拠が発言の隣から離れ、横スクロールになる。製品の要点が弱まる |

盤面では、スコアの内訳は結果カードの中に畳み、詳細（タイムライン等）は通話の上に開くシートにした。Escと「閉じる」で閉じ、次の通話を始めると自動で閉じる。

## 既知の未達
- ミッションの説明文は列の幅で1行に切れる（全文はツールチップ）。
- 1100px未満・高さ600px未満、`?present=1` は従来の表示のまま。

## 連絡先の操作改善（2026-09-19）

利用者から「直感的に操作しづらい」との指摘。既存ブランドとフォームを保つ局所改善として、連絡先利用中はシミュレーター一覧を非表示にし、専用の一覧＋編集領域にする。スマホでは一覧と入力を切り替え、「連絡先一覧へ」で戻す。空の初回は入力を直接表示する。名前／会社→任意電話→前回メモ→保存の順序とし、メール・その他メモはdetailsへ。保存操作は画面下で追従する。新たな装飾や発信機能は追加しない。実ユーザーによる改善後評価は未実施。

## 目的別の入口（2026-09-19）

繰り返された「使い方が直感的でない」という利用者の指摘を受け、既存機能の追加説明だけでなく入口を分離した。初期表示はホーム。電話の準備、連絡先、練習を選ぶ。電話の準備では練習一覧を隠す。実発信未接続を入力前に示し、CLI手順は保存後の開発者向け詳細へ。進行中の練習はホームから復帰できる。初期URLの互換変更: 練習画面に直接入る用途は `?practice=1`、既存call/replay/autostart/modeは維持。

3構成を実内容で描画・画像確認（artifacts/quality/task-entry）。A: 電話準備を左、連絡先と練習を右。B: 3等分の列。C: すべて縦積み。Aを採用した判断は実装担当によるもの（ユーザー承認済みとはしない）。Bは制限説明の折返しが多い、CはPCでも第3の目的が画面外へ出る。Aはユーザーが希望している電話準備と現状の制限を同時に示し、ほかの目的もPC初画面で見える。スマホは読み幅を優先して縦積み。

## 電話の準備画面：声をカードで選ぶ（2026-09-27）

利用者の依頼「電話できるように実装して。UIもシンプルかつ使いやすく」を受けた変更。演技する声（Gemini TTS、返事まで2〜3秒）を実電話で選べるようにし、同時に準備画面を整理した。

- 構成: 「相手」「伝えること」「声」の3区分。声は7枚のカード（キャラクター・営業・相談・案内・受付の女性／男性の声、標準）から1つ選ぶラジオグループ。音声AIと声の名前は「詳しい設定」に畳む。何も選ばなければ従来どおり「標準」。
- キャラクターのカードは、演技する声を使えるサーバーでは「演技あり・返事まで2〜3秒」、使えなければ「リアルタイム」と表示し、足りない設定をサービス名で案内する。
- 比較した案（同じ画面・実データ、1440/390で撮影）: A＝話し方・性別の切替ボタンと「演技する」チェックボックス。B＝声カード。**Bを採用**（実装担当の判断で、利用者の承認はまだ）。理由: 1回の選択で決まり、遅さと声の名前をカード上で比べられ、未設定時の降格もカード単位で示せる。Aは3つの操作を組み合わせて理解する必要があり、390幅で「キャラクター」が途中で折り返した。
- 独立レビュー（ui-reviewer）2回: 1回目 revise（P1: 消去後にカードと送信内容がずれる／1440上部の画像不足）→ 修正 → 2回目 keep。残りのP2（詳しい設定の間隔、選択中タグのずれ、句点後の空白）も修正済み。
- 操作テスト: `node scripts/ui/voice-cards.mjs`（19項目。実サーバー・電話会社なし）。Gateway（managed）は独自の声欄を持つため、この3区分と声カードは `apps/gateway/lib/phone-ui.mjs` で外し、従来の平らなフォームのまま。
- 未確認: スクリーンリーダー、OSの日本語IME、200%ズーム、この画面のダークモード、実電話での演技する声。

## UI v2：装飾を減らした暗い既定（2026-09-28）

利用者が渡した設計（design_handoff_oathra_ui_v2）に沿って作り直す。利用者の判断：暗い配色を既定にし、明るい配色も選べるように残す（`?theme=light`、ブラウザに記憶）。Arena を先に、Gateway は後で。声の一覧の試聴ボタンは、試聴音声がある声にだけ出す（新しい有料生成はしない）。

- 段階1（この版）: 色・文字・暗い既定、上部バー（マーク・文字の案内・「このパソコンで実行中」）、左の一覧（罫線で区切った行・件数）、通話画面の3列（272 | 会話 | 330）、会話の行（話者 | 言葉 | 時刻）、右の「判定」（件数・3分割の進み具合・項目ごとの値・相手の言葉・発言者と時刻）、結果は右の列の下端。`v2.css` を最後に読み込み、ハッシュ固定の style-base.css は変えない。Gateway の共有画面は `phone-ui.mjs` で v2.css を外し、現状のまま。
- 段階2: 見出し右に音量メーター（話している側だけ動く。シミュレーターは音声がないので時間で動かし、動きを減らす設定では一定）と状態・経過時間。通話中に届いた行は約2文字/70msで表示（全文は最初からDOMにある）。相手の決め手の言葉に下線と凡例。古い入場アニメーションとorbは `?present=1` 以外では止めた。
- 段階3: 電話の準備画面を2列に（だれに / 何を話すか / 声 と、右に「発信前の確認」の要約と主ボタン。最後の選択の後も主ボタンが画面内）。声は枠で囲んだ一覧（広い画面では1行）。試聴ボタンは、録音見本がある声（GPT-Live の marin・gleam・meridian。Gateway の計測済み見本と同じファイル）の行にだけ出す（2026-09-28 追記：当初「見本がない」としたのは確認不足）。演技する声（Leda/Puck）は見本がないので出さない。再生中は行の下端に2pxの線が進む。
- 段階4（狭い画面）: 見出し・状態・経過時間を上に固定、メーターの帯、話者と時刻の下に発言、通話中は判定を画面下のシート（確定した値だけ明るく✓付き、「通話を終了」）。長い会話でも最新の行はシートの上に来る。自分が電話に出るときは「切る」を入力欄の横に残し、入力中はシートを隠す。通話後は 判定 → 結果 → 証拠。ハンドオフの「最後の4行だけ表示」は、話の流れを失わないよう採らずスクロールにした。
- 操作テスト: `call-motion.mjs`（15）、`voice-cards.mjs`（25）、`arena-flow.mjs`（97）ほか。独立レビューは各段階で keep。未確認: 実機 iPhone Safari（キーボード表示中のシート）、スクリーンリーダー、200%ズーム、Gateway。
- 変更したテストの期待: arena-flow.mjs の「結果は証拠の上」を「結果は判定の列の下端、会話の横」に（設計の変更に合わせたもの）。
