# Design brief — Arena

| 項目 | 内容 |
|---|---|
| 製品 / 画面 | Oathra Arena（apps/arena/public）。`oathra demo` で開く、通話を見る・自分が出る画面 |
| 対象種別 | web-app（ローカルのデモ。録画用に `?present=1`） |
| 対象ユーザー | 音声・電話AIを作る開発者と、製品を初めて見る人 |
| 利用者が完了したい1つの仕事 | 電話を1本選び、AIと相手の会話と、相手の発言から証拠が確定していく様子を見る |
| 初見で分かってほしいこと | AIが「できました」と言っても完了にならない。相手が言ったときだけ ✓ が付く |
| 最重要の操作と結果 | 左でミッションを選ぶ → 中央で通話が始まる → 文字起こしの横で証拠が確定 → 証拠の上に結果カード（広い画面）。狭い画面では同じ順に縦へ積む |
| 今回変えないもの | scripts/verify-evidence-workspace.py が使う要素ID、style-base.css（ハッシュ固定）、`?present=1` の1画面表示、orbのアバター |
| 想定する画面幅・言語・入力方法 | 1440×900、1280×800、390×844。幅1100px以上かつ高さ600px以上は盤面（ページはスクロールしない）、それ未満は縦に積む。日本語 / 英語、ライト / ダーク |
| 利用できる部品・トークン | apps/arena/public/style-base.css。レイアウトの上書きは one-page.css（積む）と board.css（盤面） |
| 説明なしでも理解できる入口 | 左の一覧の見出し「電話を選ぶと、すぐ始まります。」と、空の中央に出る「左から電話を選ぶと、ここで始まります。」 |
| この製品らしい表現1つ | 文字起こしの隣で、相手の発言が証拠カードとして未確定→検証済みに変わる |
| 今回採用しない表現と理由 | 画面の切り替え（利用者が「1枚で」と明示）。暗い既定配色（却下済み） |
| 承認済み / 提案段階 | 画面を積む構成は PR #33 で実装済み。盤面（A案）は 2026-09-19 に3案を実画面で比べて実装者が選んだもの。利用者の承認はまだ（「1枚＝ウィンドウに収まる盤面」という要望には沿う） |

## 盤面の構成を選んだ経緯（2026-09-19）
終わった実通話（friend-hype）に3つの構成を当て、1440×900で撮って比べた。色や部品は同じで、置き方だけが違う。

| 案 | 構成 | 判断 |
|---|---|---|
| A | 左にミッションの列、中央に通話、右に結果と証拠 | **採用。** 8個のミッションが横スクロールなしで全部見える。通話前は中央が「ここで始まる」場所になる。文字起こしの隣に証拠、というこの製品らしい表現が残る。Gatewayの盤面（左で選ぶ・右で起きる）と同じ型 |
| B | 上にミッションの帯、左に通話、右に結果と証拠 | 不採用。帯は横スクロールになり、名前が隠れる。通話前の画面がほぼ空になる |
| C | 上に帯、文字起こしを広く、証拠は下に横並び | 不採用。証拠が発言の隣から離れ、横スクロールになる。製品の要点が弱まる |

盤面では、スコアの内訳は結果カードの中に畳み、詳細（タイムライン等）は通話の上に開くシートにした。Escと「閉じる」で閉じ、次の通話を始めると自動で閉じる。

## 既知の未達
- ミッションの説明文は列の幅で1行に切れる（全文はツールチップ）。
- 1100px未満・高さ600px未満、`?present=1` は従来の表示のまま。

## 連絡先の操作改善（2026-09-19）

利用者から「直感的に操作しづらい」との指摘。既存ブランドとフォームを保つ局所改善として、連絡先利用中はシミュレーター一覧を非表示にし、専用の一覧＋編集領域にする。スマホでは一覧と入力を切り替え、「連絡先一覧へ」で戻す。空の初回は入力を直接表示する。名前／会社→任意電話→前回メモ→保存の順序とし、メール・その他メモはdetailsへ。保存操作は画面下で追従する。新たな装飾や発信機能は追加しない。実ユーザーによる改善後評価は未実施。

## 目的別の入口（2026-09-19）

繰り返された「使い方が直感的でない」という利用者の指摘を受け、既存機能の追加説明だけでなく入口を分離した。初期表示はホーム。電話の準備、連絡先、練習を選ぶ。電話の準備では練習一覧を隠す。実発信未接続を入力前に示し、CLI手順は保存後の開発者向け詳細へ。進行中の練習はホームから復帰できる。初期URLの互換変更: 練習画面に直接入る用途は `?practice=1`、既存call/replay/autostart/modeは維持。

3構成を実内容で描画・画像確認（artifacts/quality/task-entry）。A: 電話準備を左、連絡先と練習を右。B: 3等分の列。C: すべて縦積み。Aを採用した判断は実装担当によるもの（ユーザー承認済みとはしない）。Bは制限説明の折返しが多い、CはPCでも第3の目的が画面外へ出る。Aはユーザーが希望している電話準備と現状の制限を同時に示し、ほかの目的もPC初画面で見える。スマホは読み幅を優先して縦積み。
