# 受付・折り返し練習: bounded design brief

対象は既存Oathra Gatewayの `/intake-pilot`。Ring Zeroのトークンを再利用し、独立したブランドやCRMを作らない。非緊急の見積相談の取り込み後に、人が内容・担当・期限・対応結果を確認するための合成データ専用試作。

## 判断の基準

- 受付しただけ、AIが終了を宣言しただけでは、確認済み/対応済みにならない
- 人が確認する回答と、その回答の根拠になる会話が隣で読める
- 担当未設定、期限未設定、回答不足、未対応を隠さない
- 「内容確認済み」と「実際に顧客へ折り返せた」を混同しない。結果は未検証の人の練習報告
- 外部通信、電話、AI抽出、督促があるような表示をしない
- 1280×800では一覧と詳細の2列。詳細が長ければ詳細領域をスクロールし、一覧は残す。390pxは縦積み
- キーボードの可視フォーカス、44px以上の主要操作、ラベル、読込・空・保存失敗・成否不明・ログイン失効を扱う
- 値の表示は textContent / DOM生成のみ。外部資産・外部フォント読込なし

## 比較する構成

A: 一覧を左、回答と会話を右にまとめた盤面。次の担当と期限を一覧で見失いにくく、既存アプリのmaster/detail構成に近い。

B: 一覧カードを上段、詳細を下段へ積む構成。同じ内容を置けるが、詳細を読むと一覧が画面から外れる。

Aを暫定採用した。比較画像を撮るためのBのCSSと再現手順をUIテストに用意したが、**ブラウザの起動/アクセスがブロックされ、両案の画像比較は未実施**。利用者承認済み・視覚確認済みとは扱わない。`frontend-design` スキルはこの環境に見つからず、インストールせず既存UIの部品と本リポジトリのui-craftを基準にした。

## 合格条件と検証状況

- Backend PASS: 合成例しか受け付けない、独立所有者、viewer書込拒否、live拒否、重複抑止、原子的保存、revision競合拒否、再読込
- Backend PASS: AI/未知話者/本文不一致の値は採用しない。回答不足で確認不可。確認・担当・期限・折り返し待ち・結果は明示的な別操作
- UI UNVERIFIED: 取込/二重操作、保存失敗、回答不足、reload、空結果、書込後の応答消失、競合、戻る、ログイン失効
- Visual UNVERIFIED: 1280/390px、長文、フォーカス、拡大表示、通常/reduced motion。未取得の画像や未実施の操作から合格を主張しない
- 別ゲート: WebKit、iPhone実機、実受電、実顧客、実担当者の運用

操作テスト: `node scripts/ui/intake-pilot.mjs`。合成用の一時SQLiteとlocalhost Gatewayのみを使う。画面の障害注入は同テスト内だけで、製品APIに隠しスイッチを設けない。
