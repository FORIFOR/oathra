# UI acceptance criteria — Gateway と Arena（アプリUI）

## 実装・導線・責務の見直し（2026-09-20）

主タスク: managed Gateway で番号・相手・目的を準備し、費用と送信先を確認して一度だけ発信を承認、進行中/終了状態・保存履歴・使用量へ戻る。実電話による追加検証はユーザーが後で行うため、本監査では外部発信しない。既存Arena/CLI/SDK契約は回帰対象。追加機能を増やすための全面再構築はしない。

| ID | 期待 | 検証環境・証拠 |
|---|---|---|
| I1 | 認証/連絡先/発信状態/料金表示/HTTPとサーバーの業務処理を明示的なモジュールで分ける。UI内で課金/発信の業務ルールを再実装しない | 依存図、ソース、module取得と既存build/typecheck/test。`docs/quality/implementation-review.md` |
| I2 | 電話と連絡先の下書きは同一ユーザーの同一タブ再読込・再認証で復元。未完了通話や指定した保存通話へ戻り、発信を再送しない。別ユーザーへ入力・履歴・遅延応答を混ぜない | 実Chrome/一時SQLite/APIの入力、再読込、ログアウト、所有者違い、終話状態の復帰。限定状態fixtureは明示・削除 |
| I3 | 連絡先の編集中データを保存前の番号で発信準備に使わない。保存の連打で重複登録せず、保存中の追加入力を消さない。別相手選択時は未保存入力を守る | 実API/DB件数とフォーム照合。電話番号は設定済み本人番号の入力のみ |
| I4 | 非同期更新が別通話の表示/停止対象や編集中の画面を上書きしない。承認前エラーと受付結果不明を区別。通信障害時に確認・復帰できる | 限定HTTP遅延/切断fixture、実Chrome、サーバーの通話件数・状態 |
| I5 | 主要操作・戻る・エラー/成功・費用の表現を維持。390px/1280px、キーボード/フォーカス、CSS200%、reduced motionを検証 | 実画面の操作と画像の目視、保存成果物。人間評価/OS IME等は別記し代用PASSにしない |
| I6 | 既存の契約・レガシー料金・CLI/SDK/練習に回帰なし。README・導入・構造説明と最新のコードが一致 | Gateway/provider/公開契約/CLI/Arena関連テスト、独立レビュー。実回線の追加試験は対象外と明記 |

## メールとパスワードでログイン（2026-09-20・実装前に固定）

通常のmanagedログイン画面はメールとパスワードのみ。既存ownerに初回設定/再設定リンクで認証情報を紐付け、クレジット・連絡先・履歴を保持する。設定リンクは期限付き・一回限り・ownerと認証版を固定し、URL fragmentから読み直後に除去。未認証で勝手に既存ownerのパスワードを設定できない。8時間のHttpOnly/SameSiteセッション・同一Origin・Bearer SDK互換を維持する。パスワードはソルト付きscrypt、ハッシュ処理の同時数/試行回数を制限し、平文を保存/ログ出力しない。失敗応答はメールの存在を区別せず、再設定/変更で旧セッションが失効する。初回設定→ログイン→再読込→変更→再ログイン、無効リンク、重複登録、失効、既存残高/連絡先保持、390px・キーボードを実Chrome/HTTP/SQLiteで検証する。メール送信やGoogle SSOは接続しない。メールアドレスの所有確認済みとは表示しない。[実行結果と証拠](../../quality/email-login.md)。

## 通話ごとの実消費（2026-09-20・実装前）

通話結果と履歴に、その通話で実際に消費したクレジットを表示する。見積額や現在の価格から推測せず、所有者に属する保存済み確保/消費/返却の記録を使う。キュー中は消費0＋確保中、実行前取消は消費0＋返却、実行確定後は消費額を表示する。通話結果UNKNOWNでも消費記録を隠さず、消費不明を0と表示しない。現在残高は過去通話直後の残高と区別する。実SQLite/HTTP/Chromeと限定中断状態で検証し、実回線・実課金とは区別する。

## 電話までの手数を減らす（2026-09-20・実装前）

managedの既存配置を維持し、番号・相手・目的→確認→「同意して電話する」の2操作とする。承認前の費用・送信先・会話保存を残し、同じ承認を別チェックで重複させない。初回認証後は8時間のHttpOnlyセッションで再読込でき、ログアウト・期限・認証情報失効で再認証になる。Cookieによる変更は同一Originのみ許可。Bearer SDK互換は維持する。確認から戻ると入力が残り、連打で下書き/発信が増えない。発信未設定では「下書きを保存」と未設定理由を表示し、実行したと誤認させない。実Chrome/SQLite/HTTPでログイン復帰・確認/戻る・所有者・390px/キーボードを確認。実発信/公開接続/決済は許可と環境不足のため別途BLOCKED。

## サービス版も元の電話画面を使う（2026-09-20）

サービス版managedの初期画面を営業用画面へ置き換えず、Arenaと同じHTML/CSSの電話番号・相手・目的、テンプレート・履歴・一般連絡先を使う。ログインと残高を追加し、秘密鍵はサービス側に保持する。確認と発信を区別し、下書き・履歴・文字起こしを所有者に保存する。ログアウトで宛先も消え、結果未確認は取消済みと表示せず照合導線がある。検証環境はローカルChrome/実Gateway API/実SQLite、既存の設定済み本人番号は入力に限定する。期待値・証拠と未実施範囲は [共有UIの検証](../../quality/shared-phone-ui.md)。

## 2026-09-19 OSS改善の固定条件

対象: v0.1.18 source、基点 `25b49fb` と作業開始時の未コミットUI編集。
主要タスク: 初心者がローカルの練習通話を選び、相手の発話に基づく結果を読み、証拠を保存して再確認する。
入力は同梱シナリオと任意の店員役の入力。成果物は結果JSON・発話証拠・決定メモ。
シミュレータは製品機能そのものとして使い、新しいモックや架空の通話記録は加えない。
成功は実予約の成立ではなく、練習の判定と成果物の一致。比較軸は開始手順数、必要な秘密情報、再送の副作用、保存と復帰の可否。競合の実測なしに優越を主張しない。

| ID | 測定環境・期待する結果 | 検証方法・証拠 |
|---|---|---|
| Q1 | Node 22以上、macOS、ローカルのみ。既定demoはAPIキー不要、外部モデルを起動しない | CLI起動と `/api/brains`。環境・コマンド・exit codeを `artifacts/quality/` と検証報告に記録 |
| Q2 | 初画面に練習・成果物・最初の操作。Playの例文を編集して送信できる | Chrome実画面、キーボード操作・スクリーンショット・実サーバのイベント |
| Q3 | 完了判定、処理終了、保存済みを区別。保存失敗でも結果をダウンロードし、保存だけ再試行できる | 実ファイルシステム障害と復帰。GET結果と保存JSON・summaryを照合 |
| Q4 | 二重開始・応答喪失で同じ操作を重複実行しない。再読込で同じ通話を参照できる | 実HTTPの冪等キー・衝突・異なるOrigin・終了後入力。ブラウザ再読込で通話IDと件数を照合 |
| Q5 | 公開SDKとCLIが同じ実記録を同じ結果に判定。互換性とexperimental境界が明示される | 既存公開録音由来入力をexportし両結果を比較。文書とexportsを確認 |
| Q6 | 1440×900、1280×800、390×844、200%相当reflow、長文、キーボード、reduced motionで主要操作を失わない | 実Chromeの操作ログ・画像。日本語OS IME実操作は別記し、合成イベントだけでPASSにしない |
| Q7 | build、typecheck、既存test・UI回帰が成功する | 各コマンドとexit code。既存試験がモックを使う範囲は実接続証明と区別 |
| Q8 | 独立コンテキストで重大欠陥を再確認。実ユーザー・ネイティブ・実発信をWeb試験で代用しない | 独立レビュー記録。実機/外部権限不足はBLOCKED、対象外の状態はNOT_APPLICABLE |

判定はPASS / FAIL / BLOCKED / NOT_APPLICABLE。未実施はPASSにしない。初回の結果は `docs/quality/verification.md`、再監査は `docs/quality/reaudit.md`、修正後の結果は `docs/quality/fixes.md` に記録する。

公開サイト（site/）の合格条件は docs/design/ACCEPTANCE.md。こちらは操作する画面の基準。

## 1. Task / clarity
主要タスクを短いGiven/When/Thenで定義し、実際に操作するテストを用意する。
例: 初期状態→主ボタン→入力→実行→結果表示→やり直し。
APIエラー、権限拒否、二重操作、キャンセルのうち対象機能に関係するものをテストする。
CTAのクリック成功だけでなく、約束された結果が得られることを確認する。

## 2. Responsive / content
検査幅: 390×844 と 1440×900（`pnpm test:ui` が撮影）。ノートPCの 1280×800 でもGatewayの盤面がスクロールなしで収まること。必要なら320 CSS pxのreflowも検査する。
各幅で主要情報が隠れず、意図しない横スクロールがないこと。
日本語の長い名前・見出し・改行、0件・1件・多数件を既存の実記録と実操作で確認する。未実施の件数条件は明示する。
PCとスマホを同じレイアウトの縮小版にせず、主操作の配置を確認する。
対象がiPhoneの場合は実機Safariも別途確認する。

## 3. Accessibility
通常サイズの文字コントラストは原則4.5:1以上、大きい文字は3:1以上。
例外やUI部品の非テキストコントラストは、該当するWCAG要件に照らして確認する。
プロジェクト目標としてタッチターゲット44×44 CSS pxを推奨する。
これはWCAG 2.2 AAの最低値が常に44pxという意味ではない。
キーボードの主操作、focus表示、dialogのフォーカス管理を実操作で確認する。
axeの自動チェック0件だけで全面的な適合としない。

## 4. Visual direction
briefに沿った文字・余白・レイアウトの一貫性を画面として確認する。
視線がまず主操作または主要コンテンツへ向かうことを確認する。
装飾、影、色、アイコンを増やす前に、不要な情報を削る。
システムフォント、角丸、グラデーション等を一律禁止しない。用途で判断する。

## 5. Motion and responsiveness
押下の反応、loading、完了、エラーへの遷移を実画面で確認する。
アニメーション時間は採用トークンに合わせる。競合の計測値を捏造しない。
通常motionを確認し、別途reduced-motionが本質的でない動きを抑えることを確認する。
速度は実測した環境・方法・数値を記録する。未測定を高速と評価しない。

## 6. Completion
最新コードでtests・画像・独立レビューが揃っている。
未確認の項目をPASSに変えない。P0/P1が残れば未完了。
回帰比較の基準画像は人間の承認後に保存する。AIが勝手に更新しない。

## 7. このリポジトリで自動確認しているもの（`pnpm test:ui`）
Gateway: サインイン→準備→同意→目的→確認→チェックなしの承認拒否→承認→進行→ふつうの言葉の結果と相手の発言の引用→履歴、
盤面がウィンドウに収まる、横スクロールなし、44px未満の操作部なし、内部フィールド名が画面に出ない、ページエラーなし。
Arena: ミッション選択が残り、広い画面では横、狭い画面では下で通話が始まる。冒頭の録音告知、文字起こしと証拠、結果の配置、詳細とEsc復帰、戻る。
追加の `pnpm test:arena-outcome` は実HTTP/ファイルの保存障害と復帰、取消、冪等開始、キーボードでの開始・入力、通信断と再読込、成果物照合を検証する。
自動確認していないもの: 実電話モード、フォローアップ送信、キーボードだけでの全機能網羅、OS日本語IME、スクリーンリーダー、通常motion、実機iPhone、apps/ios。

## 2026-09-19 再監査の修正条件（実装前に固定）

macOS/Chrome・実ローカルサーバ・製品シミュレータで、(R1) 同一開始120ms連打と戻る後の別開始でも稼働通話を増やさず、再読込/履歴閲覧後も進行中通話に戻れる、(R2) 不正JSON/型を4xxで拒否し通話件数が増えない、(R3) 日本語/英語のシナリオ説明と成果物の日付が一致する、(R4) 新設回帰がCIの実行対象になること。証拠は `artifacts/quality/fixes/` と修正報告。失敗時の無条件再送は禁止。外部接続・実ユーザー・OS固有の未試験をPASSにはしない。

## 電話番号入力（2026-09-19）

番号・相手名・依頼内容→正規化した宛先の確認→未発信JSON保存。入力変更で古い確認を無効化し、同一タブの再読込では入力を復元、消去で破棄する。無効/複数番号は推測せず拒否。Web/LINE/CLIは同じ番号契約を使う。入力だけで発信・課金しない。ArenaはCLI引継ぎ、汎用LINEは下書きまでという現在の制約を隠さない。1280/390px・キーボード・Core/API/CLI dry-runと承認なし拒否を実測し、外部LINE/PSTN試験は別記する。

## 一般連絡先（2026-09-19）

実Chrome＋一時ローカル保存先で、名前または会社名のみで登録できること、電話番号なしでは電話依頼ボタンが無効であること、会社・メモ・前回電話内容が保存／編集／サーバー再起動後に一致することを検証する。電話履歴は同番号の保存済み記録に限定し、手入力メモと区別する。保存競合は409で上書きせず、履歴だけの破損では連絡先編集を維持する。

検証コマンドは `node scripts/ui/contacts.mjs`、`pnpm exec vitest run apps/arena/src/contacts.test.ts apps/arena/src/contacts-api.test.ts`。証拠と実施範囲は `docs/quality/general-contacts.md`、`artifacts/quality/general-contacts/` に記録する。

連絡先UX追加条件: 連絡先表示中は練習一覧が見えない。390pxで初回入力、一覧への戻り、保存した相手の再選択、未保存入力を維持した一覧往復ができる。保存と電話依頼入力は異なる操作として表示する。連絡先以外の既存練習フローが動く。

## 電話依頼から練習シナリオへの遷移

`?lang=ja&phone=1` から友達との電話シナリオをクリックしたとき、同じフォームへ戻るだけでなくシミュレーターを選択し練習が開始すること。watchは会話、playは会話と返信入力を表示する。入力中の電話依頼は保持し、キャリアへの発信は行わない。検証: `node scripts/ui/scenario-navigation.mjs`、既存`arena-flow.mjs`の戻る操作を挟まない回帰ケース。修正前FAIL/修正後PASSと画像は `artifacts/quality/scenario-navigation/`。

## 共通通話終了操作

友達との電話練習でplay/watch両方の通話見出しに「通話を終了」を表示。クリック中は二重実行を抑止し、受付のみで終了扱いにせずGET/SSEで終端確認。確認後は「通話を中断しました」を表示し、終了操作を隠す。返信・一覧往復・中断を実ブラウザとAPIのendReason=cancelledで照合する。390px横溢れなし。`node scripts/ui/call-controls.mjs`、証拠`artifacts/quality/call-controls/`。実発信は対象外。

## 目的別ホーム

クリーンな初回URLでは目的を選ぶホームが表示され、練習は自動開始しない。電話準備は実発信できない旨を入力前に表示し、練習一覧が混在しない。連絡先と練習への入口がある。ホームに戻っても進行中の練習を再開し終了できる。390px/640px横溢れなし。実APIの通話状態まで照合する。`node scripts/ui/task-entry.mjs`と`artifacts/quality/task-entry/`を証拠にする。従来練習フローは`?practice=1`で回帰検証し、ホーム自体のテストとは分ける。
