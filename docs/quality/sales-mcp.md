# Claude Code・ChatGPT向け営業MCPの実装・検証

2026-10-02 JST / 基点 `db56271` と既存の未コミット変更に追加。

**公開・営業電話の受け入れ判定: BLOCKED。** HTTP MCP、本人のOAuth接続許可、接続解除、営業下書きの確認画面を追加した。固定HTTPS配備、公式Claude Code・ChatGPTの実接続、実在する営業依頼を使った下書きから発信・結果取得までの確認は完了していない。公開済み・営業成果達成とは扱わない。

## 対象の流れ

1. Oathraに本人がログインし、確認した商品と連絡の根拠がある相手を登録する。
2. `/connect` のコマンドまたはURLをClaude Code・ChatGPTに設定する。
3. 接続先の名前・戻り先・権限を本人が確認し、OAuth接続を許可する。
4. AIが登録済み情報を読み取り、営業電話の下書きを1件作る。
5. 本人が `reviewUrl` で相手・用件・クレジットと通話／保存の説明を確認する。必要な共通同意と、その1件の発信承認を別々に行う。
6. AIは通話状態と根拠を読む。通話内の合意を契約締結や外部予約台帳への登録とみなさない。

接続手順は[Claude Code・ChatGPT](../integrations/claude-chatgpt.md)。事前に宛先・費用・回数を委任する既存の自動発信APIは[別の接続](../integrations/multibot.md)で、このOAuth接続には委任の作成・変更権限を与えない。

## 検証と証拠

ローカルHTTP検証には既存の実operatorとSQLiteのnative backupを使用した。既存の設定から必要な認証・精算方式だけをコピーし、外部providerキーを渡さず、workerを起動しない。`mode=simulator` はloopback検証の設定で、シミュレーター通話自体は実行していない。実在しない顧客・商品・会話・決済を作成していない。

実行環境はNode v25.2.1、macOSのChromeとloopback HTTP。記録の `providerRequests: 0` は外部操作を実行しない構成を表す固定値であり、通信監視による実測値ではない。

最初の検証はハーネスが既存精算方式に必要な音声モデル設定をコピーしておらず、起動時に `configure_live_prices` で停止した（`http-oauth.json`、0項目）。必要な既存値のコピーを修正して再実行し、失敗記録も保持した。架空の単価や利用履歴で補わない。

2回目は27項目、3回目は追加の権限・競合・UI検証を含む48項目。下書き確認に目的・候補日時の表示を追加した後、4回目の48項目で対象ファイルhashが検証中に変わっていないことを確認した。既存実営業記録がないため、目的・候補日時を含むmission画面そのものの実表示、下書き成功・status成功はBLOCKEDのまま。全検証で架空の営業データは追加していない。

画像は非公開情報を含まない未ログイン画面だけを保存し、rootも目視確認した。認可操作は画面の構造を参照した自動操作であり、初見の実利用者によるUX試験ではない。画像中の本人3回上限は隔離環境の省略時初期値で、公開用テンプレートの本人1回・全体5回とは区別する。実環境の上限は変更していない。

独立担当は最終記録の7ファイルのSHA256と現在のコードの一致、48件のassert、PC／狭幅画像を確認した。新規P1/P2の指摘は残っていない。保存画像は画面上部だけで、認可後・下書き・発信画面の視覚証拠にはならない。

一般公開のための実設定は[公開準備](public-service.md)を継続する。公式クライアントとの相互運用、実利用者による初回接続、営業下書きの成功・冪等性・発信確認・実通話の完了は未検証。接続やローカル検証を外部利用者数・営業成果へ数えない。
