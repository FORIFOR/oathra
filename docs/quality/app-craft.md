# アプリ全体の操作・画面品質

2026-10-02 JST。ユーザーの「アプリ全体を対象にする」という指定に基づく、[公開サイト・入口の改善](award-craft.md)の続き。受賞水準は目標であり、自己採点で受賞可能・審査合格と認定しない。基点は `db56271` と既存の未コミット変更。既存作業は保持する。

## 対象と確認条件

ログイン後のホーム、電話の依頼準備、依頼一覧、既存の通話報告、予定、練習、連絡先、設定、managed phone のアカウント・クレジット、設定から到達する従来の詳細画面 `/workspace` を対象とする。

「既存の依頼と結果を理解し、次の電話の準備を行い、費用と許可範囲を確認できる」ことを画面品質の条件とする。公開 LP の大きな見出しや演出を操作画面に持ち込まず、次に判断するもの・根拠・状態を近くに置く。

検証環境は実 DB の native backup。worker は起動せず、外部 provider の資格情報を渡さない。登録・購入・発信は停止し、全体予算はゼロ。架空の利用者・商品・会話・購入・クレジット履歴を追加しない。本人データを含む画面の証拠画像は、撮影時だけ個人情報を非表示にし、その範囲を各記録に明示する。非表示にした文字自体のタイポグラフィ検証には用いない。

## 実画面から見つかった点

- 狭幅の依頼準備では、長い停止案内と見出しが入力前の大部分を占め、メニューの右端が見切れていた。
- 設定の縦ナビがスマートフォンの約300pxを占め、選んだ設定の本文が下に押し出されていた。
- 報告では長い用件が先に並び、相手の言葉と結果を確認するまでが遠かった。
- クレジットは残高と確保中の単位・意味が読み取りにくく、休止説明が重複し、閉じる操作が初期表示外に出ていた。
- `/workspace` は同じオリジンで有効なログイン cookie があっても、トークンの再入力を要求した。実際に bootstrap が200でもログイン欄が表示されることを再現した。
- ソース確認では、利用状態がプレリリース停止を優先していない箇所、失敗も含む一覧を「完了」と呼ぶ箇所、入力欄とラベルの関連付け不足も見つかった。
- 実通信を800ms遅らせると、依頼準備からホームへ移動した後に古い非同期描画が届き、URLはホームなのに依頼画面になる問題を再現した。画面遷移の世代を確認してから描画するよう修正した。
- 練習一覧では、390px指定時にモバイルのレイアウト幅が509pxへ広がっていた。`innerWidth`だけとの比較では見逃すため、指定幅・`clientWidth`も合わせて確認し、一覧の最小幅を修正した。
- 実通信断で英語の例外だけが出て、同じ画面に復帰する操作がなかった。読込失敗には日本語の説明と再読込を用意し、保存・送信の応答不明は再送せず履歴を確かめる案内にした。
- cookie共有への変更のレビューで、古い画面の入力が別タブで切り替わったアカウントへ送られる懸念を検出した。従来画面と本体のリクエストを読み込み時のアカウントへ固定し、不一致時は旧フォームを破棄して読み直す。初回bootstrap後に本人を固定してから履歴と利用状況を取得する。

新規依頼の改善前画像は変更前の画面。ホーム・報告・設定の一部の画像は最初の小さな修正を含む中間版であり、完全な改善前画像とは扱わない。画像・時点・ソースハッシュの関係は個別の検証記録に残す。

## 構成の選択

ホームについて、均等な統計カードを増やす案、全画面を一つの入力欄に寄せる案、報告を主列・利用状態を補助列に置く案を比較した。既存記録を確認して次の電話を準備する用途に合わせ、最後の案を選ぶ。実績に見える装飾的な数値やグラフは追加しない。

依頼準備は入力から確認へ進む階層を揃え、声の任意設定は必要時に開く。停止中という事実は常時示し、細かい上限は開いて読めるようにする。相手、費用、同意、AIに任せる範囲は最終確認から削らない。クレジットとアカウントは残高・購入・利用履歴、本人情報・AI連携・パスワードを区分し、通信失敗を空履歴と混同しない。

## 検証の記録

今回の証拠は [2026-10-02-app-craft](evidence/2026-10-02-app-craft/) に保存する。実装担当と別のエージェントによる操作・画像レビューを行う。人間による初見テストや独立した外部審査の代用とはしない。

- `/workspace` の初回実セッション検証は16項目 PASS。トークン入力から cookie への移行、入力消去、再読み込み、設定への復帰、サーバー側ログアウト、実セッション失効、停止表示、1440 / 390px のはみ出し、実行時例外を確認。[操作記録](evidence/2026-10-02-app-craft/workspace-after.json)。実装後の狭幅画像から、初回設定の文が細く折り返す問題を見つけ、行幅と44pxの操作領域を修正して再確認した。前段の画像・結果は `workspace-round-a.*` に保持する。この16項目は後述の本人固定修正より前であり、最終認証処理は別途確認した。
- アカウント・クレジットは実ブラウザ46項目と追加10項目 PASS。[個別レビュー](evidence/2026-10-02-app-craft/phone-account-review.md)。実残高・実台帳・実際に空の購入履歴を使い、通信断と復帰、320 / 390 / 1440px、閉じる操作と再表示位置、暗色を確認した。実購入・決済・新規利用者・台帳の空状態や100件以降のページングを作って代替していない。
- 固定後の最終版で、独立担当が13画面を1440 / 390 / 320pxの計39条件で操作。横はみ出し、ラベル未関連付け、実行時例外は検出しなかった。[画面記録](evidence/2026-10-02-app-craft/final-routes.json)。モバイルは実機ではなくChromeの幅エミュレーション。
- 実通信断から日本語の説明と直接再読込で依頼フォームへ復帰し、既存cookieで詳細画面へ移動して設定へ戻る4項目 PASS。[最終操作記録](evidence/2026-10-02-app-craft/app-independent-interactions-final.json)。800ms遅延で費用設定・依頼準備からホームへ移動する2経路とも、古いFetchが完了した後もホームを維持した。[最終遷移記録](evidence/2026-10-02-app-craft/navigation-race-final-fixed.json)。中間の `navigation-race-final.json` は実行中にソース変更があったため、最終版の証拠には使わない。
- 本人固定の独立検証は21項目 PASS。実Networkで本人一致ヘッダー、実セッション削除による401、旧フォーム破棄とdocument全体の再読込を確認。[本人固定レビュー](evidence/2026-10-02-app-craft/account-binding-review.md)。別の実利用者への切替と409応答は実行せず、該当分岐は静的確認に限る。
- 報告の開閉とフォーカス、空の商品フォームの必須入力、Tab順、720pxの折返し、CSSの200%拡大、動きを減らす設定を独立確認。[7項目の記録](evidence/2026-10-02-app-craft/app-accessibility-narrow.json)。CSS拡大はブラウザ標準のズーム検証やスクリーンリーダー検証の代わりにはしない。managed phone の本人設定・クレジットも320pxで開閉を独立再確認した。[4項目と未検証1項目](evidence/2026-10-02-app-craft/phone-independent.json)。
- 実装担当はSafariでも実際に空の依頼・商品入力を確認し、架空値を保存せずに必須入力と開閉を操作した。個人情報を含まない[最終依頼画面](evidence/2026-10-02-app-craft/final-new-safari-desktop.png)は内容の差替えやマスクなし。親担当もこの画像と最終ホーム・練習・報告・依頼のデスクトップ／狭幅画像を目視した。

JS構文検査と `git diff --check` は成功。今回は静的フロントエンドの差分に対応する確認を行い、前回のビルド・OAuth検証を今回の再実行結果として数えていない。

[独立最終レビュー](evidence/2026-10-02-app-craft/independent-final-review.json)は8観点 PASS、実データ・外部受け入れが必要な3観点 BLOCKED。今回観測されたP1/P2は修正後に残っていない。これは全状態で不具合がないことや、全業務が完了することの認定ではない。

隔離プレビューのプロセスを確認して正常終了し、前後35業務行のハッシュ一致と一時DB削除を確認した。[データ保全・終了記録](evidence/2026-10-02-app-craft/preview.json)。原本DB・本番env・稼働中の公開プロセスは変更していない。ソースと証拠の最終SHA-256は [manifest](evidence/2026-10-02-app-craft/final-manifest.json) に保存する。

ホーム等の実データを伏せた画像は、情報の配置・幅の確認に使う。日時、用件、相手の言葉を含めた実画面の読み取りは実データで行い、非公開の値を証拠ログへ転記しない。通信遅延と通信断はChromeの実Network設定を変更して発生させ、fetch応答の差替えはしていない。
