# Local Arena contract (source after v0.1.18)

The stable integration entry is `oathra/evidence` (`verifyTranscript`, `defineCall`, `EvidenceEngine`, `evaluate`), not the Arena HTTP server. Pin a released package version. These source changes have not been published; v0.1.18 release assets do not contain them. Node >=22, ESM; the monorepo's `@oathra/*` packages are internal workspace imports. The existing CLI exit contract remains 0=complete, 2=valid but incomplete/failed/constraint violation, 1=input/execution error.

## Responsibilities

Core/evidence owns validation and completion. Runtime owns execution/cancellation. Adapters own authenticated external connections. Arena renders runtime outcomes; it must not infer a booking from HTTP 201, stream completion, or an agent's statement. Conversation evidence does not prove a venue's backend booking. `summary.md` and the downloadable summary are rendered by the same replay module.

Arena HTTP and its downloadable envelope are **experimental**, local, single-operator interfaces. They are not a hosted authorization boundary. Loopback Host and same-Origin are required; do not expose the server via a proxy or on an untrusted machine. CLI `demo` now registers only the built-in scripted agent. `demo --allow-models` explicitly enables model selection: OpenAI/Gemini send conversation data to their configured provider and may charge; Ollama uses its configured host. This is a deliberate safe-default behavior change, not a guarantee that arbitrary provider code is sandboxed. API credentials in the environment alone no longer enable model selection in demo. No PSTN adapter is connected to Arena.

The browser keeps one current call per tab in sessionStorage, including while browsing history. Starting while it is running resumes it instead. A read failure never automatically starts a replacement. This is a UI workflow limit, not a server-wide concurrency limit: independent API clients may intentionally run multiple calls. Repeated HTTP requests still require the same Idempotency-Key for server-enforced deduplication.

## Requests and states

- `POST /api/calls`: required nonempty string scenarioId, optional string brain and `watch|play` mode; speed must be finite and positive, calleeName must be a string when provided. JSON must be an object; null, arrays, primitives, malformed JSON and invalid field types return 400 `INVALID_INPUT` before execution. HTTP 201 acknowledges a call, not completion. `Idempotency-Key` (8–128 ASCII letters/digits/underscore/hyphen) is recommended. Same key and normalized input returns the same call; conflicting input returns 409 `KEY_CONFLICT`. Keys live only for this server process. After process loss, reconcile saved calls; never automatically repeat an external operation. Legacy clients without a key retain their previous behavior (each POST is a new call).
- `GET /api/requests/:key`: read-only lookup of an acknowledged start request. Returns callId or 404 `REQUEST_UNKNOWN`. UI recovery never resubmits an unknown start after a restart; inspect saved calls before explicitly starting anew.
- `GET /api/calls/:id`: `status=running|done|error` is execution state; `result.status` is evidence judgment. `persistence=pending|saved|failed|disabled` is independent. A client unable to read this response must show an unconfirmed state. API replies are additive to the previous shape.
- `GET /api/calls/:id/events`: existing named SSE `call` events and terminal `done`. On reconnect read the full GET snapshot, rebuild it, then reconnect. Sequence numbers can be replayed; consumers must not apply side effects twice. The UI resumes with `?call=<id>`; after a server restart it tries the saved replay.
- `POST /api/calls/:id/hangup`: requests runtime cancellation; repeated requests are harmless. HTTP 200 is acceptance, not proof that cancellation completed. Observe `endReason=cancelled` on the final GET. No claim that an external committed action is undone.
- `POST /api/calls/:id/reply`: nonempty string `text`, human input in play mode only, refused with 409 after termination. Reply delivery is not durable or idempotent; do not auto-retry on an ambiguous network failure.
- `POST /api/calls/:id/save`: retries persistence of the same in-memory outcome, never executes another call. 409 before outcome, 503 on write failure, 200 with persistence status otherwise. With save disabled this stays disabled.
- `GET /api/calls/:id/artifact`: download `{schemaVersion:1, transport:"simulator", callId, contract, result, events, transcript, traces, metrics, endReason, intake, summary}`. Available only after outcome (otherwise 409). May contain conversation data; downloads are explicitly user initiated, never uploaded.
- `GET /api/replays/:id`: existing recording format; its saved contract, not today's edited scenario, determines historical requirements. Existing recordings remain readable. File writes are synchronous but not a filesystem transaction; partially written recordings may be unreadable. Only `persistence=saved` means all writes returned successfully (not an fsync durability guarantee).

New machine-readable errors: `LOCAL_ONLY`, `ORIGIN_DENIED` (403), `INVALID_INPUT` (400), `KEY_CONFLICT`, `CALL_ENDED`, `NOT_READY` (409), `INTERNAL_ERROR` (500). Existing error messages remain for older clients. This does not version all legacy endpoints; consumers must handle unrecognized errors and unknown additive fields.

Local simulation requires no approval state. Result unavailable during disconnect is unconfirmed, not success/failure. Human play has no independent ground truth; the UI labels its false-completion assessment as unassessed. External approvals/credentials belong to Gateway/provider workflows and were not newly authorized or certified here.

`GET /api/replays/:id/artifact` returns the same envelope as the live artifact; its transport comes from the recorded `call.started` event (unknown if absent). Old replay JSON remains unchanged. The runnable [SDK example](../../examples/verify-recording.mjs) accepts the same transcript-check JSON as `oathra verify`; install the pinned public package in the host application, not the internal workspace imports. The artifact envelope is not a transcript-check input: use its contract and final transcript with the actual call-local reference date and connection state as described in INTEGRATION.md.

## Phone-number intake (experimental)

`POST /api/phone/prepare` validates a phone number, name and instruction through the shared contract package. It returns an inert versioned phone-request draft, not a call. No carrier is invoked. The UI allows review and JSON export; direct browser dialing remains unconnected. The CLI accepts the same file with `call --request-file <json> --dry-run`; execution requires explicit `--approve-request`. This format is separate from the evidence artifact and transcript-check formats. See [phone-input.md](phone-input.md) for limits, channel behavior and verification.
