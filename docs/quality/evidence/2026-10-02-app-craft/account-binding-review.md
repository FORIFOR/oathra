# アカウント固定の修正確認

2026-10-02 JST。対象は旧 `/workspace` と `/app/` のセッション本人固定。実装者とは別のエージェントによる確認であり、人間の評価や別モデルの独立評価ではない。

## 実行結果

Chrome 154.0.8037.58 / macOS 27.0.1、隔離プレビュー `http://127.0.0.1:61758`、既存の実 operator を使用。21 項目 PASS。詳細・時刻・実行対象の SHA-256 は `account-binding-review.json`。

- 旧画面で初回 bootstrap による本人確認後、再読込 GET に `x-oathra-account` が付くことと、値が認証本人に一致することを CDP の実 Network イベントで確認。
- `/app/` の履歴・月上限・電話設定・残高履歴・公開提供状況・購入履歴・購入状況再確認の実 GET は、すべて本人一致のヘッダー付き。Bearer を継続送信していない。
- 実サーバーへのセッション削除後、旧画面の再読込は 401 となり共有ログインへ移動。
- 同様に `/app/` の購入状況再確認が 401 となると、`performance.timeOrigin` が変わり、navigation type が `reload` となった。購入フォームは消去され、認証済みナビゲーションは非表示になった。
- 実行時例外なし。対象 JS 2 ファイルは実行中の hash 不変、`node --check` は両方 PASS。

初回 bootstrap と、失効して新しい document が作られた後のログイン画面の公開提供状況 GET は、本人がまだ確定していないためヘッダーなし。これを異常には数えていない。

## 静的確認

`sessionOwner` は初回 bootstrap の本人へ固定される。サーバーに cookie が別アカウントへ切り替わった場合の照合処理があり、画面側は 401 / `session_account_changed` で旧画面を破棄する。`/app/` は epoch と route version で旧応答を抑止し、`history.replaceState` の後に `location.reload()` を実行する。ログイン画面表示・再ログイン時も本人と旧画面 state をリセットする。今回の修正範囲に追加の具体的な P1 / P2 は見つからなかった。

## 未検証と副作用の範囲

別の実利用者の認証情報は使用していないため、2 アカウント間の実切替と実 409 応答は未検証。実 401 による document 再生成までを実証した。架空アカウント、架空応答、fetch の差替え、通話・決済・送信は行っていない。新しい業務レコードも作成していない。

token・cookie・owner ID・email・リクエスト／応答本文は証拠へ保存せず、ヘッダーの存在・本人一致・Bearer 有無だけを記録した。スクリーンショットは作成していない。実検証で作成した own session は同じ検証内で削除し、専用 Chrome とその一時プロファイルを閉じた。プレビューサーバーは維持した。

再実行は repo ルートから `node docs/quality/evidence/2026-10-02-app-craft/account-binding-review.mjs`。実 operator token を既知のローカルファイルからメモリだけに読み込み、認証と自分のセッション失効を行う。元 JSON を保存したい場合は、実行前に出力名を新しい名前へ変更する。
