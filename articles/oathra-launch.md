AIに電話をかけさせる仕組み自体は一晩で動きます。厄介なのはその先でした。

- 席が取れていないのに「予約できました」と言い切る
- 留守番電話に向かって2分間、予約を頼み続ける
- 予算を超えた値段を、会話の流れで受けてしまう

全部、実際に自分の携帯に電話をかけさせて起きたことです。そこで、**完了の判定をモデルから取り上げてコードに移す**ランタイムを作りました。

https://github.com/FORIFOR/oathra

## 何をするものか

```bash
npx oathra demo
```

ブラウザで AI 同士が電話を始めます（API キー不要）。片方がレストラン、片方が予約を取りたい客です。19時が満席なので店が19時半を出し、AI が受け、名前を伝え、店側の「ご予約承りました」で初めて MISSION COMPLETE になります。

結果は要約ではなく、相手の発言に紐づいた証拠です。

```json
{
  "field": "time",
  "value": "19:30",
  "source": "callee",
  "transcript": "19時はいっぱいですが、19時半でしたら空いております。",
  "span": "19時半",
  "explicit": true,
  "verified": true
}
```

完了は次の式で決まります。

```text
完了 = 接続済み ∧ 日付.検証済み ∧ 時刻.検証済み ∧ 人数.検証済み ∧ 確定.検証済み ∧ 制約を満たす
```

AI 側が「確定しました」と言っても、記録されるだけで `confirmed` は埋まりません。埋めるのは相手の「ご予約承りました」だけです。

## 証拠エンジンのルール

決定論的なパーサとルールで処理していて、ここには LLM を使っていません。

- 「19時はいっぱいですが、19時半なら」→ 19:00 の証拠は作らない（否定節）
- 「13日、いや14日」→ 14日が残り、上書きの履歴が付く
- 「たぶん大丈夫」→ 同意でも確定でもない
- 「承りました」の後に金額が変わる → 確定は古くなり、取り直しが必要
- 「わかりました、他を探します」→ 受諾ではない

これを壊しに行くために、意地悪な店員を1万通り生成して回すコマンドがあります。

```bash
oathra eval --adversarial 10000
# never-confirm / wrong-restate / negate-then-offer / silent-hangup / caller-echo-trap
# False Completion: 0 / 10000 adversarial runs
```

開発中にこのファズが本物のバグを何度も捕まえました。「21,100円」がカンマで節分割されて「100円」になり AI が受諾した、というのが最初の一件です。

## 本物の電話

同じランタイムがそのまま電話に繋がります。

```bash
oathra setup phone      # 音声エンジンと電話会社を選ぶ
oathra phone doctor     # どの層が壊れているか
oathra call --to +81…   # 発信
```

電話会社（Twilio 直結 / Plivo・自前 SIP は LiveKit ゲートウェイ経由）と音声モデル（GPT-Live / OpenAI Realtime / Deepgram + LLM + TTS）は別々に選べます。

実際に自分の携帯にかけた記録です。

| 回 | 構成 | 起きたこと |
|--|--|--|
| 1 | Deepgram + GPT-4o-mini + TTS | 最初の返答まで 11.8 秒。「聞こえますか」を連呼された |
| 2 | 同上 + TTS ストリーミング | 応答 2.2 秒。留守電に2分話しかけ、雑音で13回中断 |
| 3 | GPT-Live（全二重） | 返答まで約 0.4 秒。6分25秒の雑談がエラーなしで成立 |

3回目で「これは使える」と思いました。GPT-Live はセッション $0.05/分、Twilio は日本の携帯宛 ¥28.78/分です。

## 正直な現状

- Twilio 直結と GPT-Live は実通話で検証済み
- Plivo と Custom SIP は各社ドキュメント準拠で実装したが PSTN は未検証
- MCP 対応は v0.2
