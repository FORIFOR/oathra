電話をかけるAIエージェントの [Oathra](https://github.com/FORIFOR/oathra)（Apache-2.0）を書いています。方針はひとつで、**完了したかどうかをモデルに決めさせない**。相手の発言だけを読む別のコードが判定します。

その判定を、おとといまで自分で間違えていました。同じ依頼に対する5つの返事を並べます。予約が取れているのは最後の1つだけですが、5つとも「はい」に聞こえます。判定結果はすべて、公開しているコードに流し直して確認したものです。

依頼はいつもこれです。

```
AI: 9月25日の19時半に2名でお願いできますか。田中と申します。
```

## 1. 仮押さえ

```
店: かしこまりました、9月25日19時半に2名様で仮でお席を押さえておきます。
    確定はまた折り返しご連絡します。
```

判定は **未完了**。抽出された値は**ひとつもありません**。

店員は日付も時刻も人数も正しく復唱しています。それでも何も残しません。「仮で」「確定は折り返し」という語が同じ発言の中にあるからです。埋まった項目の数で完了を決める実装なら、ここは満点で通ります。電話をかけた目的だけが達成されていない状態で。

## 2. 別提案

```
店: その日ですと21時しか空いておりません。いかがでしょうか。
```

判定は **未完了**、抽出も無し。

数字は言われました。ただしそれは「あなたの予約」としてではなく、質問として出されています。罠は次のターンで、AIはたいてい「では21時でお願いします」と答えます。店員のターンから `21:00` を取り、そのあとAIが同意っぽいことを言えば、**誰も承諾していない予約が全項目埋まった状態で完成します**。店員の提案は、こちらが受けて、相手がそれを受理するまで提案のままでなければいけません。

## 3. 言い間違いの復唱

```
店: 9月26日19時半、2名様、田中様でご予約承りました。
```

判定は **未完了**。`time=19:30` と `partySize=2` は入り、**日付だけが空のまま**です。

「承りました」は本物の確定表現で、時刻と人数はこちらの依頼と一致しています。日付だけが1日ずれている。こういう電話は実際にあって、しかも会話は最後まで和やかに終わります。依頼と違う値は、正しい値を上書きせず、単に埋まらない。結果として「日付が未確認」という形で表に出ます。

## 4. 取り消し

```
店: 9月25日19時半、2名様、田中様でご予約承りました。
店: あ、失礼しました、その日は貸切でした。お受けできません。
```

判定は **未完了**。……と、おとといまでは**なっていませんでした**。ここは `completed` を返していました。

取り消しの判定パターンが、拒否の語の近くに「予約」「注文」という語を要求していたからです。席が埋まっただけの店員はそんな言い方をしません。「貸切でした」「満席になってしまいました」「その日は定休日でした」と言います。予約は同じように消えているのに、私のコードはそれを成功と呼んでいました。

直し方は意図的に狭くしました。**相手の「空きがない」語**（満席・貸切・休業・定休・埋まって・空いておりません）が、**それより前に**発せられた確定を取り消します。

- どんな拒否でも取り消すのではありません。予約後の「カードはお受けできません」は支払いの話であって、キャンセルではない。
- 「前に」だけです。予約の**前**にある「19時は満席ですが19時半なら」は、まったく影響を受けません。

[PR #37](https://github.com/FORIFOR/oathra/pull/37) で両方向のテスト付きで入れました。

## 5. 本当の「はい」

```
店: 9月25日19時半、2名様、田中様でご予約承りました。
```

判定は **完了**。`{ date: 2026-09-25, time: 19:30, partySize: 2, confirmed: true }`。

英語版の同じ文（"You are all set for September 25 at 7:30 pm, party of two."）は、今日まで**何も返しませんでした**。「未確定」ではなく、空です。

エンジンの中に「相手がこちらの提案に同意した」と「相手が予約を確定した」という2つのリストがあり、"all set" は後者にだけ入っていました。だからこちらが提案した値は1つも検証されず、確定は「その時点で確定していた値」に紐づく仕様なので、裏に何もない確定は古いものとして落とされる。**重なるべき2つのリストが重なっていないと、ごく普通の文で画面が真っ白になります。**

見つけたのは、他人のスレッドにコメントを書きながら、自分の公開ページに英語のログを貼ってみたときでした。英語の自然な承諾5つのうち動いたのは3つ。毎日使っている日本語側は無事でした。教訓は正規表現の話ではなく、**テストしていない言語が壊れている言語だ**ということです。

## どう担保しているか

リリースごとに、上のような形に加えて留守番電話・取次ぎ・保留後の返答・方言の確認・言い間違いの復唱を混ぜた**1万件の敵対的対話**を流し、次の1行を絶対条件にしています。

```
False Completion: 0 / 10000 adversarial runs
```

誤完了とは、ランタイムが「完了」と報告したのに、相手側の真値が「承諾していない」と言っている状態です。0以外は不合格。これは判定が万能だと証明するものではなく、**私が知っている「通話が嘘をつく形」がすべて塞がっていること**と、変更でどれか1つが開いた瞬間に落ちることだけを保証します。

逆向きの誤り（本当は予約が取れているのに「未完了」と言う）は許容しています。かけ直せば済む電話だからです。反対向きは、店の前に立っている客が出ます。

## 判定が変わるところを見る

26秒、音声なし。店の返事を差し替えるたびに同じコードが走り直し、項目が入れ替わります。カメラの寄りとカーソルと字幕は編集で足したもので、画面と判定は編集していません。

## 自分のログで試す

音声AIを運用しているなら、いちばん速いのは自分の文字起こしを貼ってみることです。インストールも鍵も不要で、入力はタブの外に出ません。

**https://forifor.github.io/oathra/check.html**

発言者を付けて1行ずつ。

```
AI: 9月25日の19時半に2名でお願いできますか。田中と申します。
店: かしこまりました、仮でお席を押さえておきます。
```

店員の「はい」を「いいえ」と読んだら、それは私が欲しいバグです。対応している言い回しは有限のリストで、リストはどの言語でもどこかが短い。リポジトリは Apache-2.0 です: [FORIFOR/oathra](https://github.com/FORIFOR/oathra)。
