「資料確認は今日中に。メール返信は明日に回す」

AIとの会話でこう決めたあと、もう一度タスク管理ツールへ入力する。その手間を減らすために、会話からTODOを残せるOSS「AI Meeting」を開発しています。

タスクを追加するだけでなく、会話の途中で完了や延期に変え、次回も続きから使えます。入力によるタスク管理は、[公開アプリ](https://ai-meeting.web.app/#tasks)で登録せずに使えます。

まずは、実際のGeminiの返答とタスク変更を収録した45秒のデモです。

@[youtube](qLenE6R7-nI)

[45秒のデモをYouTubeで開く](https://youtu.be/qLenE6R7-nI)

*入力はmacOSの合成音声、返答は実際のGeminiです。専用の録画レイアウトを使い、確認待ちの変更は録画スクリプトが入力内容との一致を調べてから反映しています。人がマイクへ話した実験や、すべての変更が無条件に適用される例ではありません。*

この記事では、作るうえで分ける必要があった3つの状態を説明します。

1. モデルが提案した変更
2. 保存先へ反映できた変更
3. 利用者に実際に聞こえている音声

音声のタスク管理に限らず、ツールを呼び出すAIや、音声に反応するアバターを作るときにも使える設計です。

## 会話の返答を、そのままタスクの正解にしない

たとえば「資料確認を今日中に終える」と話したとき、モデルにはタスク操作の引数と、根拠になる発話の引用を返してもらいます。

```json
{
  "operations": [
    {
      "action": "add",
      "title": "資料確認",
      "due": "今日",
      "quote": "資料確認を今日中に終える"
    }
  ]
}
```

これは説明用の入力例です。実装では、このJSONが正しい形をしているだけでは保存しません。

- `quote` が最新のユーザー発話に存在するか
- `title` と `due` が引用の中に存在するか
- 更新対象のIDが実際にあるか

といった条件を `TaskLedger` で検査します。期限も、最初から推測した日時に変換せず、発話に含まれる表現として扱います。

### 音声と文字起こしは、同じ順番で届くとは限らない

ここで困るのが、音声モデルのツール呼び出しに文字起こしが追い付いていない場合です。引用が確認できないからといって、検査を緩めると推測による変更も通ってしまいます。

現在の実装では、引用の照合に失敗した場合だけ、文字起こしを最大1,200ms待ち、50msごとに再確認します。それでも確認できなければ、画面に変更案を置きます。

```text
ツール呼び出し
  → 形式・発話の引用を検査
      → 確認できる：保存処理へ
      → 引用だけが未確認：文字起こしを短時間待つ
          → なお未確認：画面に変更案を表示
              → 利用者が確認：保存処理へ
```

変更案はメモリー上に置き、未確認のまま永続化しません。モデルにも `needs_user_confirmation` を返し、まだ記録済みとは案内しないようにします。

この照合は、音声認識の誤りをすべて解消する仕組みではありません。文字起こし自体が誤る可能性は残ります。そのため、保存したタスクは一覧で読めて、編集・完了・延期できる形にしています。

実装: [TaskLedger](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/packages/conversation-core/src/tasks.ts) / [文字起こしを待つ処理](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/apps/web/src/session/SessionController.ts#L331)

## 「反映できる変更」と「保存できた変更」も分ける

タスクの変更内容が妥当でも、ブラウザーの保存が失敗することはあります。画面の配列だけを書き換えて成功扱いにすると、再読込したときに消えます。

個人用のタスクはIndexedDBに保存します。読み取り、変更、書き込みを一つの `readwrite` トランザクションで行い、**トランザクションの完了後に成功を返します。**

```ts
// TaskWorkspaceの完了判定を抜粋
tx.oncomplete = () => {
  db.close();
  resolve(result);
};
tx.onabort = () => {
  db.close();
  reject(failure ?? storageError());
};
```

複数タブの操作も考慮しています。編集前のタスクと保存先の最新状態を比較し、すでに別のタブで変わっていれば、古い内容で上書きせずに最新状態の確認を促します。

個人用はこのブラウザーへの保存で、端末間の自動同期はありません。JSONでバックアップを保存・復元できます。別に用意したチーム共有は認証付きのクラウド保存で、個人用と保存先を分けています。

実装: [TaskWorkspace / PersistentTaskLedger](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/apps/web/src/state/taskWorkspace.ts)

## 音声UIは、モデルの生成状態だけでは動かせない

もう一つ、画面のオーブにも似た問題があります。

モデルから音声データが届いていても、再生バッファに積まれている間は、まだ利用者には聞こえません。逆に、モデルの生成が終わっても、スピーカーの再生は続いていることがあります。

そこでオーブには、マイク入力とスピーカー再生のPCMから求めた音量を渡します。音声データの受信だけで「話しています」へ切り替えず、既存の再生処理から取り出した音声を使います。

| 実際の状態 | オーブの表示 |
| --- | --- |
| 会話状態がユーザーの発話を検出している | 聞いています |
| 応答を待っている・音声はまだ再生されていない | 考えています |
| 再生処理から音声が出ている | 話しています |
| セッション終了・エラー | 残った音量より終了状態を優先 |

状態を決める関数は、描画処理から分離しました。以下は優先順位を示す抜粋です。

```ts
if (phase === "error") return "error";
if (phase === "ending") return "ending";
if (phase === "ended") return "ended";

// 生成が終わったあとも、再生は続く場合がある
if (levels.playing) return "speaking";

// 音声を生成中でも、再生前なら「考えています」
if (avatar === "THINKING" || avatar === "SPEAKING") {
  return "thinking";
}
```

音量はRMSから求め、時間とともに減衰させます。再生中の短い無音で表示が細かく切り替わらないよう、再生処理の稼働状態も使います。マイクのミュートは入力だけを止め、流れているAIの返答まで無音扱いにはしません。

見た目には [LerSent001/orb](https://github.com/LerSent001/orb) のMITライセンスのガラス表現を組み込みました。[オーブのプレビュー](https://ai-meeting.web.app/orb-preview)で、入力・思考・出力の表示を切り替えて確認できます。このページは見た目のサンプルで、マイク取得やAI接続は行いません。

描画は最大30fps・512×512、画面が隠れている間は停止します。WebGPUが使えない場合はCSSの表現へ切り替え、動きを減らす設定にも対応しています。音量のために別のマイクを開いたり、音声を追加送信したりする必要はありません。

実装: [voiceActivity.ts](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/apps/web/src/session/voiceActivity.ts) / [描画と検証範囲](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/docs/voice-orb.md)

## 試す入口と、検証した範囲

用途に応じて入口を分けています。

| やりたいこと | 入口・条件 |
| --- | --- |
| タスクを保存し、次回も使う | [タスク管理](https://ai-meeting.web.app/#tasks)。無料・登録不要、ブラウザー内に保存 |
| 音声とアバターの動きを見る | [アバターデモ](https://ai-meeting.web.app/vrm-demo)。録音済み音声などを再生 |
| 実際にAIと会話する | [公開アプリ](https://ai-meeting.web.app/)。メール確認済みアカウント、1回3分・1日1回まで。UTC日付で集計し、全体枠にも上限あり |
| コードを動かす・接続先を変える | [GitHubの起動手順](https://github.com/FORIFOR/AI-meeting/blob/main/README.ja.md)。Node.js 22を推奨、pnpm 10.12.2 |

今回のオーブ実装を含むコミットでは、自動テスト1,099件、型検査、通常ビルドとOSS配布用ビルドの検査が合格しています。これは人が感じる会話の自然さや、顧客環境での導入結果を測った数字ではありません。

実Geminiのデモ、タスクの再読込後の復元、チーム共有のクラウド検証は、それぞれ条件を分けて[検証記録](https://github.com/FORIFOR/AI-meeting/blob/2ccc83385736a167573afbb8ee40c8d6b6a67b7d/docs/validation.md)に残しています。アプリはベータ版で、長時間の会議や任意のMeet・Zoom環境での動作を、このデモだけで確認したことにはしていません。

チームでの「会話→TODOを確認→保存→次回へ引き継ぐ」を検討する方には、[5名・30日・1回3分の提供範囲](https://github.com/FORIFOR/AI-meeting/blob/main/docs/team-deployment.md)を用意しています。導入やカスタマイズの相談は[非公開フォーム](https://ai-meeting.forifor.chatgpt.site/ja#business)で受け付けています。

コードはApache-2.0で公開し、オーブ、VRMモデルなど第三者のコード・素材には個別の条件を記載しています。実装を読みたい方は、[AI Meetingのリポジトリ](https://github.com/FORIFOR/AI-meeting)をご覧ください。
